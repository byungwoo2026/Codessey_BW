1. 큰 그림 — Mini Git은 무엇인가

세부 코드는 잠시 잊고, 전체 모양부터 잡습니다.

한 문장 요약

Mini Git = "커밋(점)"들을 "부모 화살표(선)"로 이은 그래프를 메모리에 만들고, 그 위에서 탐색(위상 정렬·BFS), 검색(역색인), 정렬(병합 정렬)을 직접 구현한 프로그램.

1-1. Git을 일기장에 비유하면

비유
  • 커밋 = 일기장 한 쪽. 내용(메시지) + 쓴 사람 + 날짜 + "이전 쪽 번호"가 적혀 있다.
  • 부모 커밋 = 그 "이전 쪽 번호"가 가리키는 쪽. 쪽은 앞 쪽만 알고, 뒤 쪽은 모른다.
  • 브랜치 = 책갈피(포스트잇) 이름표. "main은 이 쪽, feature는 저 쪽". 쪽을 복사하는 게 아니라 이름표만 붙이는 것이다.
  • HEAD = "지금 내가 어느 책갈피를 들고 있나". 새 쪽을 쓰면 들고 있는 책갈피가 새 쪽으로 옮겨 간다.
  • 브랜치가 갈라진다 = 같은 쪽에서 두 사람이 각자 다음 쪽을 써서 이야기가 두 갈래가 된다.

1-2. 직접 재생해 보기 — 명령 시뮬레이터

아래는 이 프로젝트를 실제로 실행한 결과를 한 명령씩 재생합니다. [다음 ▶]을 누르며 왼쪽 터미널과 오른쪽 그래프가 어떻게 바뀌는지, 그리고 아래 설명을 같이 보세요. (끝까지 보면 "브랜치가 갈라지는 것 = 같은 부모를 가진 커밋이 둘 생기는 것"이 눈에 들어옵니다.)

  1. 검증 — INIT 했는지, 메시지가 비어 있지 않은지 (아니면 MiniGitError).
  2. 부모 정하기 — 현재 브랜치가 가리키는 커밋(tip)이 부모. 없으면(첫 커밋) 부모 없음 [].

  4. 그래프에 저장 — graph.add(commit): dict에 hash → Commit 저장, 부모의 "자식 목록"에도 등록. (부모가 이미 있는지 검사 → DAG 보장)
  5. 브랜치 이동 — branches["main"] = "c002" (이름표를 새 커밋으로).
  6. 역색인 갱신 — 메시지를 split+lower 한 단어마다 keyword_index["add"], ["login"] 에 c002 추가, author_index["alice"] 에도 추가.
  7. cli 가 [main c002] Add login 이라는 한 줄로 바꿔 출력.

A. 파이썬 문법 — 이 코드를 읽는 데 필요한 것만

A-1. 함수 · 리스트 · 슬라이싱 · 인덱스

한 줄 풀이: 함수는 "재료를 받아 결과를 돌려주는 기계", 리스트는 "번호 붙은 서랍 줄"입니다. 번호는 0부터 시작합니다.

예제
def double(x):          # 함수: 재료(x)를 받아 결과를 돌려준다
    return x * 2

commits = ["c001", "c002", "c003", "c004"]
print(double(21))
print(commits[0], commits[-1])        # 첫 번째, 마지막 (번호는 0부터)
print(len(commits))                   # 개수
print(commits[:2], commits[2:])       # 슬라이싱: 앞 2개 / 3번째부터 끝까지
commits.append("c005")                # 뒤에 추가
print(commits)
실행 결과
42 c001 c004 4 ['c001', 'c002'] ['c003', 'c004'] ['c001', 'c002', 'c003', 'c004', 'c005']

쓰이는 곳: 병합 정렬이 items[:middle], items[middle:] 로 리스트를 반으로 자르고, 큐를 queue[front] 로 읽습니다.

A-2. 딕셔너리(dict) — 이름표로 값을 바로 꺼내는 서랍장 ★ 가장 중요

한 줄 풀이: {키: 값} 모음. 키를 알면 값을 번호 세기 없이 바로 꺼냅니다. 학교 사물함에서 "3번 사물함!" 하고 바로 여는 것과 같습니다.

예제
branches = {"main": "c003", "feature": "c002"}   # {키: 값}
print(branches["main"])                 # 키로 바로 꺼내기
print(branches.get("dev"))              # 없으면 None (에러 안 남)
print("feature" in branches)            # 키가 있나?
branches["dev"] = "c001"                # 추가/수정
for name, tip in branches.items():      # 키와 값을 같이 순회
    print(name, "->", tip)

index = {}
index.setdefault("login", []).append("c002")   # 칸이 없으면 빈 리스트를 만들고 추가
index.setdefault("login", []).append("c003")
print(index)
실행 결과
c003 None True main -> c003 feature -> c002 dev -> c001 {'login': ['c002', 'c003']}

쓰이는 곳(전부 dict): 커밋 저장소 {hash: Commit}, 브랜치 {이름: hash}, 역색인 {단어: [hash…]}, 거리표 {커밋: 거리}. 과제의 "hash로 빠르게 찾는 해시맵"이 바로 파이썬 dict입니다.

A-4. 클래스(class)와 self — 데이터와 기능을 한 덩어리로

한 줄 풀이: 클래스는 설계도, 객체는 설계도로 만든 실물. self는 "이 객체 자신"입니다. __init__은 객체가 만들어질 때 자동 실행되는 준비 함수입니다.

예제
class Counter:
    def __init__(self):          # 객체가 만들어질 때 자동 실행
        self.count = 0           # self.xxx = 이 객체가 가진 데이터

    def up(self):                # 메서드 = 객체의 기능
        self.count += 1
        return self.count

a = Counter()
b = Counter()
print(a.up(), a.up(), b.up())    # a 와 b 는 서로 따로 센다
실행 결과
1 2 1

쓰이는 곳: CommitGraph, InvertedIndex, Repository, HashGenerator. 각각 "자기 데이터(self.xxx)"를 들고 있고 메서드로 조작합니다.

쓰이는 곳: Commit 이 dataclass. 과제의 "커밋 노드 최소 필드: hash, message, author, timestamp, parents" 를 그대로 필드로 적었습니다.

A-6. 예외(try / except / raise) — 에러를 문장으로 바꾸기

한 줄 풀이: raise = "문제 발생! 하던 일 중단하고 신호를 던짐", try/except = "그 신호를 받아서 처리". 프로그램이 죽지 않고 에러 문장만 출력하게 만듭니다.

예제
class MiniGitError(Exception):
    pass

def find_branch(branches, name):
    if name not in branches:
        raise MiniGitError(f"Unknown branch: {name}")   # 문제 발생! 던지기
    return branches[name]

try:
    find_branch({"main": "c001"}, "dev")
except MiniGitError as error:                           # 받아서 처리
    print("에러 문장:", error)
print("프로그램은 계속 진행됨")
실행 결과
에러 문장: Unknown branch: dev 프로그램은 계속 진행됨

쓰이는 곳: 잘못된 입력이면 Repository 가 MiniGitError("Unknown branch: x") 를 던지고, cli.execute 가 잡아서 그 메시지를 그대로 출력합니다. 그래서 REPL 이 절대 죽지 않습니다.

A-7. lambda 와 key 함수 — "무엇을 기준으로 비교할지" 넘기기

한 줄 풀이: lambda c: c.author 는 "c를 받아 c.author 를 돌려주는 이름 없는 작은 함수"입니다. 정렬 함수에 기준만 갈아 끼우는 용도로 씁니다.

예제
people = [("Bob", 30), ("alice", 25)]
by_name = lambda p: p[0].lower()           # lambda = 이름 없는 작은 함수
print(by_name(people[0]))

def pick(items, key):                      # key 함수를 받아서 "기준값"을 뽑는 예
    return [key(x) for x in items]

print(pick(people, lambda p: p[1]))        # 나이를 기준으로
print(pick(people, by_name))               # 소문자 이름을 기준으로
실행 결과
bob [30, 25] ['bob', 'alice']

쓰이는 곳: merge_sort(commits, key=lambda c: c.timestamp) / key=lambda c: c.author.lower(). 정렬 코드 한 벌로 날짜순·작성자순을 모두 처리합니다 ("비교 기준을 바꿔 정렬" 요구사항).

A-8. 문자열 — split · lower · strip · f-string · 따옴표 인자
예제
import shlex
message = "  Add Login  Feature "
print(message.split())                          # 공백 기준 자르기 (연속 공백 무시)
print([w.lower() for w in message.split()])     # 소문자로
print(repr(message.strip()))                    # 양끝 공백 제거
name, n = "Alice", 3
print(f"{name} made {n} commits")               # f-string: 중괄호 안에 값
print(f"c{7:03d}")                              # 3자리 0 채움
print(shlex.split('COMMIT "Add login feature"'))  # 따옴표 덩어리는 하나로
실행 결과
['Add', 'Login', 'Feature'] ['add', 'login', 'feature'] 'Add Login Feature' Alice made 3 commits c007 ['COMMIT', 'Add login feature']

쓰이는 곳: 역색인의 키워드 추출(split+lower = 과제의 최소 기준 그대로), 출력 문장 만들기(f-string), 명령줄을 단어로 자르기(shlex.split).

A-9. while + 위치 번호로 만드는 큐 (이 프로젝트의 BFS/위상정렬 패턴)

한 줄 풀이: 큐는 "먼저 들어온 것이 먼저 나가는 줄서기". 리스트 맨 앞을 pop(0) 하면 느려서, 위치 번호(front)만 앞으로 밀며 읽습니다.

예제
queue = ["a"]            # 시작점
front = 0                # 맨 앞 위치 번호
children = {"a": ["b", "c"], "b": ["d"], "c": [], "d": []}
order = []
while front < len(queue):
    current = queue[front]      # 맨 앞 꺼내기
    front += 1                  # 위치 번호만 앞으로 (pop(0) 은 느리다)
    order.append(current)
    for child in children[current]:
        queue.append(child)     # 뒤에 줄 세우기
print(order)
실행 결과
['a', 'b', 'c', 'd']

이 모양(queue.append 로 뒤에 넣고, front 로 앞에서 꺼냄)이 위상 정렬 · BFS · 조상 탐색 3곳에 똑같이 나옵니다. 이 패턴만 익히면 graph.py 가 전부 읽힙니다.

B. Git 개념 — 최소한

커밋 (commit)

"이 시점의 기록" 한 장. 메시지·작성자·시각·부모 커밋을 가집니다. 첫 커밋만 부모가 없습니다(뿌리 커밋).

커밋 하나를 가리키는 이름표. 새 브랜치를 만들어도 커밋이 복사되지 않습니다. 그래서 "가볍다"고 합니다.

부모 → 자식

커밋은 부모를 가리키고(parents), 부모는 자식을 모릅니다. 자식 방향이 필요하면(PATH 등) 따로 기록(_children)해 둬야 합니다.

C. 자료구조 · 알고리즘 개념

C-1. 그래프 · 노드 · 간선 · DAG ★
비유 — 가계도 / 지하철 노선도

사람(또는 역) = 노드(점), 연결선 = 간선. "부모→자식"처럼 화살표 방향이 있으면 방향 그래프입니다.

  • 순환(cycle) = 화살표를 따라가다 출발점으로 돌아오는 길. (A→B→C→A)
  • DAG = Directed(방향 있음) Acyclic(순환 없음) Graph. 이름 그대로입니다.
  • 트리와의 차이: 트리는 부모가 항상 1개지만, DAG 는 부모가 2개 이상일 수 있습니다. 실제 Git 의 merge 커밋은 부모가 2개라서 트리가 아니라 DAG 입니다.

✅ DAG (정상)

  c001
   ↑   ↑
 c002 c003     ← 두 갈래, 되돌아오는 길 없음
   ↑
 c004

❌ 순환 (불가능)

 A → B
 ↑   ↓
 └─ C         ← A에서 출발해 A로 돌아옴

왜 커밋은 순환이 안 생기나? 커밋은 이미 존재하는 커밋만 부모로 가리킬 수 있고, 부모는 항상 자식보다 먼저 만들어졌습니다. 화살표가 항상 "과거"로만 뻗으니 미래로 갔다가 돌아올 수 없습니다. 코드에서는 CommitGraph.add 가 "부모가 이미 저장돼 있어야 한다"를 검사해서 이것을 강제합니다.

C-2. 해시(hash)와 해시맵 — 왜 "빠르게" 찾을 수 있나
  • hash(해시값) = 커밋을 구분하는 이름표 문자열 (우리는 c001). 진짜 Git 은 커밋 내용을 SHA-1 로 계산한 긴 문자열(a1b2c3d…)을 씁니다.
  • 해시맵 = 키를 계산해 "몇 번 칸"인지 바로 알아내는 서랍장. 사물함 번호를 알면 줄 서지 않고 바로 가는 것과 같습니다.
  • 그래서 조회가 평균 O(1) — 데이터가 10개든 100만 개든 거의 같은 시간.
  • 반대로 리스트에서 "c777 어디 있지?" 하고 앞에서부터 찾으면 O(n) — 100만 개면 최대 100만 번 확인.

과제에서 "커밋 저장소는 hash로 빠르게 찾을 수 있어야 한다(예: 해시맵 기반)" → CommitGraph._commits: dict[str, Commit]

C-3. 큐(queue)와 BFS(너비 우선 탐색) ★
비유 — 연못에 돌 던지기

돌을 던지면 물결이 가까운 곳부터 한 겹씩 퍼집니다. BFS 가 바로 그렇게 "출발점에서 1걸음 거리 → 2걸음 거리 → …" 순서로 퍼져 나갑니다.

  • 큐 = 먼저 들어온 것을 먼저 꺼내는 줄. BFS 의 "다음에 볼 곳 목록"입니다.
  • 처음 어떤 점에 닿은 순간의 걸음 수가 곧 최단 거리입니다. (가까운 곳부터 보니까 더 짧은 길이 나중에 나올 수 없음)
  • visited(이미 본 점)를 기록해야 같은 점을 두 번 보지 않고 빙빙 돌지 않습니다.
  • 시간복잡도 O(V + E) — 점 V개와 선 E개를 각각 한 번씩만 봅니다.

3장의 "최단 경로" 시각화에서 직접 확인합니다.

C-4. 위상 정렬(Topological Sort) ★
비유 — 수강신청 선수과목

"자료구조를 들으려면 프로그래밍기초를 먼저" 같은 선수 관계가 있을 때, 모든 과목을 선수과목이 항상 앞에 오도록 한 줄로 세우는 것이 위상 정렬입니다. 커밋에서는 부모 = 선수과목, 자식 = 후수과목. 그래서 "부모가 먼저 출력되는 로그" = 위상 정렬 순서입니다.

  • 위상 정렬은 DAG 에서만 가능합니다 (순환이 있으면 서로가 서로의 선수과목이라 줄을 세울 수 없음).
  • 정답이 하나가 아닙니다. 갈라진 두 가지(c003, c005)는 어느 쪽이 먼저여도 됩니다. 우리 구현은 항상 같은 결과가 나오도록 규칙(만든 순서)을 정해 두었습니다.
  • 대표 방법이 Kahn 알고리즘: "기다리는 부모가 0개인 커밋부터 꺼낸다" (3장 시각화).
C-5. 정렬 · 안정 정렬 · Big-O(시간복잡도)

Big-O = 데이터가 n개로 늘 때 "일이 얼마나 늘어나나"를 나타내는 표기입니다. 정확한 초(秒)가 아니라 늘어나는 모양을 봅니다.

C-6. 역색인(Inverted Index) ★
비유 — 책 뒤쪽의 "찾아보기"

"로그인"이 몇 쪽에 나오는지 알고 싶을 때 책을 처음부터 넘기지 않고, 뒤쪽 찾아보기에서 "로그인 → 12쪽, 87쪽"을 바로 찾습니다. 그 찾아보기가 역색인입니다.

보통 색인(정방향) :  c002 → ["add", "login", "feature"]    ← 커밋에서 단어를 찾음
역색인             :  "login" → ["c002", "c003"]            ← 단어에서 커밋을 찾음 ★

검색할 때마다 모든 커밋을 훑는 대신, 커밋을 만들 때 미리 표를 만들어 두는 것입니다. (3장 시각화에서 직접 비교)

3-1. 위상 정렬 (Kahn) — LOG 가 "부모 먼저"인 이유

수강신청으로 이해하기

각 과목 옆에 "아직 안 들은 선수과목 수" 숫자를 적습니다. 0인 과목은 지금 들을 수 있습니다. 하나 듣고(=출력) 나면 그 과목을 선수과목으로 가진 과목들의 숫자를 1씩 줄이고, 0이 된 과목을 다음 후보 줄에 세웁니다. 이걸 반복하면 선수과목이 항상 앞에 오는 순서가 나옵니다.

알고리즘 5줄 요약

  1. 모든 커밋의 waiting_parents(= 부모 수)를 센다.
  2. waiting_parents == 0 인 커밋(뿌리)을 queue에 넣는다.
  3. queue 맨 앞을 꺼내 출력 순서에 추가한다.
  4. 그 커밋의 자식들의 waiting_parents 를 1 줄인다. 0이 된 자식만 queue 에 넣는다.
  5. queue 가 빌 때까지 3~4 반복.

아래에서 왼쪽 버튼(브랜치 그래프)으로 기본 동작을, 오른쪽 버튼(병합 그래프)으로 "부모가 둘인 커밋 m 은 두 부모가 모두 나올 때까지 기다린다"는 핵심 포인트를 확인하세요.

코드 위치

mini_git/graph.py → CommitGraph.topological_order

핵심 3줄: waiting_parents[child] -= 1 / if waiting_parents[child] == 0: / queue.append(child)

시간복잡도

O(V + E): 각 커밋을 한 번 꺼내고(V), 각 부모-자식 연결을 한 번 줄입니다(E).

순환이 있으면 일부 커밋이 영영 0이 못 돼서 len(queue) != 전체 가 됩니다 → 순환 감지.

3-2. 최단 경로 (BFS) — PATH 와 ANCESTORS

PATH 의 정의 (과제 원문)

"커밋-부모 연결을 무방향 간선으로 간주했을 때의 최단 경로(간선 수 최소). 경로가 없으면 No path. 최단 경로가 여러 개면 hash1->hash2->... 문자열이 사전순으로 가장 작은 경로."

왜 무방향? feature 끝(c004)에서 main 끝(c006)으로 가려면 공통 조상(c002)까지 부모 방향으로 내려갔다가, 다시 자식 방향으로 올라가야 합니다. 화살표 방향만 따르면 갈 수 없는 길입니다.

우리 구현은 2단계입니다 (사전순 조건을 가장 깔끔하게 만족시키는 방법):

  1. 도착점에서 BFS를 돌려 모든 커밋의 "도착점까지 거리"를 구한다 (파란 숫자).
  2. 출발점에서 걷기: 매 걸음, "거리가 정확히 1 작은 이웃" 중 hash 가 가장 작은 쪽으로 간다.
왜 "걸을 때마다 가장 작은 hash"만 고르면 전체가 사전순 최소일까? (평가에서 물을 수 있음)

최단 경로는 모두 같은 개수의 커밋을 지납니다. 같은 길이의 두 문자열을 사전순 비교하면 처음으로 달라지는 칸이 승부를 결정합니다. 그러니 앞 칸부터 가능한 가장 작은 것을 고르면 뒤 칸이 어떻든 전체가 최소입니다. (사전 편찬에서 "가"로 시작하는 단어가 "나"로 시작하는 단어보다 항상 앞인 것과 같은 이치.)

이것이 정말 맞는지 테스트로 증명했습니다: 임의의 DAG 수천 쌍에 대해 "모든 경로를 전부 나열해서 문제 정의대로 고른 정답"과 우리 결과를 비교 (test_shortest_path_matches_brute_force_including_lexicographic_tie_break).

ANCESTORS 는?

같은 BFS 인데 이웃을 "부모"로만 제한한 것입니다. visited 로 같은 조상을 두 번 안 담습니다 (병합 커밋이 있으면 같은 조상에 이르는 길이 2개). 가까운 조상부터 나옵니다.

코드: graph.py → ancestors

왜 DFS 가 아니라 BFS?

DFS 는 "한 길로 끝까지" 가는 방식이라 처음 찾은 길이 최단이라는 보장이 없습니다. BFS 는 가까운 곳부터 퍼지므로 처음 도착한 순간이 최단입니다.

모든 경로를 나열해 비교하는 방법은 길이가 길어지면 경우의 수가 폭발(지수)합니다.

3-3. 병합 정렬 — LOG --sort-by=...

카드 두 더미 합치기

이미 정렬된 카드 두 더미가 있으면, 맨 위 카드 둘만 비교해서 더 작은 쪽을 가져가기를 반복하면 한 번에 정렬된 한 더미가 됩니다. 병합 정렬은 이 "합치기"를 이용해서, 카드를 1장씩이 될 때까지 반으로 쪼갰다가 거꾸로 합쳐 올라갑니다.

"""Mini Git이 공통으로 쓰는 '데이터 모양'과 '에러 종류'를 정의한다.

- Commit        : 커밋 한 개 (그래프의 점 하나)
- HashGenerator : 겹치지 않는 커밋 hash를 발급하는 기계
- MiniGitError  : 사용자에게 그대로 보여줄 에러 메시지를 실어 나르는 예외
"""

from __future__ import annotations

from dataclasses import dataclass, field
from datetime import datetime


class MiniGitError(Exception):
    """사용자 입력이 잘못됐을 때 던지는 예외.

    예외 메시지가 곧 화면에 출력되는 문장이다.
    표준 메시지 예) "Invalid args", "Unknown branch: dev", "Unknown commit: c999"
    """


@dataclass
class Commit:
    """커밋 노드. 그래프에서 '점' 하나에 해당한다.

    필수 필드 5개 (과제 요구사항)
    - hash      : 커밋의 고유 이름표. 예) "c001"
    - message   : 커밋 메시지. 검색(SEARCH)의 재료
    - author    : 작성자 이름
    - timestamp : 커밋을 만든 시각 (datetime). LOG --sort-by=date 의 기준
    - parents   : 부모 커밋 hash 목록. 이것이 그래프의 '화살표(간선)'다.
                  첫 커밋은 부모가 없어서 빈 리스트 [] 다.
    """

    hash: str
    message: str
    author: str
    timestamp: datetime
    parents: list[str] = field(default_factory=list)


class HashGenerator:
    """세션 내에서 절대 겹치지 않는 커밋 hash를 발급한다.

    방식: 증가 카운터. c001, c002, c003, ...
    카운터는 1씩 늘기만 하고 줄지 않으므로 같은 번호가 두 번 나올 수 없다.
    (INIT을 다시 해도 이 발급기는 유지되므로, 세션 전체에서 유일하다.)

    진짜 Git은 커밋 내용을 SHA-1로 계산한 해시를 쓴다.
    여기서는 '유일성 보장'과 '직접 입력하기 쉬움'을 위해 카운터를 택했다.
    """

    def __init__(self) -> None:
        self._counter = 0

    def next_hash(self) -> str:
        """다음 hash를 발급한다. 1000번째부터는 c1000처럼 자릿수가 늘어난다."""
        self._counter += 1
        return f"c{self._counter:03d}"

STEP 2sorting.py — 병합 정렬 (직접 구현)

하는 일: sorted() / list.sort() 가 금지이므로 손으로 만든 정렬. key 함수로 기준을 바꿔 끼웁니다. 이 파일은 다른 파일에 의존하지 않아서 혼자 완성·검증할 수 있습니다.

"""직접 구현한 정렬 알고리즘 (병합 정렬, merge sort).

과제 규칙상 파이썬 내장 정렬 기능은 쓸 수 없어서 손으로 만들었다.

병합 정렬의 성질 (평가에서 자주 묻는 부분)
- 평균 시간복잡도  : O(n log n)
- 최악 시간복잡도  : O(n log n)   <- 입력이 어떤 순서든 똑같다
- 추가 메모리      : O(n)         <- 합칠 때 새 리스트가 필요하다
- 안정 정렬 여부   : 안정(stable)  <- 키가 같은 항목끼리는 원래 순서를 유지한다

왜 병합 정렬인가?
- 퀵 정렬은 평균은 빠르지만 최악이 O(n^2)이고 안정 정렬이 아니다.
- 로그에서는 '날짜가 같은 커밋들은 원래(부모 먼저) 순서 유지'가 자연스럽다.
  안정 정렬이면 그게 공짜로 해결된다.
"""

from __future__ import annotations

from typing import Any, Callable, TypeVar

T = TypeVar("T")


def merge_sort(items: list[T], key: Callable[[T], Any] | None = None) -> list[T]:
    """items를 key 기준 오름차순으로 정렬한 '새 리스트'를 돌려준다. 원본은 안 건드린다.

    key는 '무엇을 기준으로 비교할지'를 알려주는 함수다.
    기준만 바꿔 끼우면 같은 정렬 코드로 날짜순/작성자순을 모두 처리할 수 있다.
        merge_sort(commits, key=lambda c: c.timestamp)      # 날짜 기준
        merge_sort(commits, key=lambda c: c.author.lower()) # 작성자 기준

    아이디어(분할 정복)
        1) 반으로 쪼갠다            [5, 2, 4, 1] -> [5, 2] [4, 1]
        2) 각각 정렬한다(재귀)       [2, 5]       [1, 4]
        3) 정렬된 두 조각을 합친다   [1, 2, 4, 5]
    조각 길이가 0~1이면 이미 정렬된 것이므로 그대로 돌려준다(재귀의 끝).
    """
    if key is None:
        key = _identity

    if len(items) <= 1:
        return list(items)

    middle = len(items) // 2
    left = merge_sort(items[:middle], key)
    right = merge_sort(items[middle:], key)
    return _merge(left, right, key)


def _identity(value: T) -> T:
    """key를 안 주면 값 자체를 기준으로 쓴다."""
    return value


def _merge(left: list[T], right: list[T], key: Callable[[T], Any]) -> list[T]:
    """이미 정렬된 두 리스트를 하나로 합친다. 합치기가 병합 정렬의 핵심이다.

    양쪽 맨 앞 항목을 비교해서 더 작은 쪽을 꺼내 결과에 붙이기를 반복한다.

    안정 정렬이 되는 이유: 키가 같을 때(<=) '왼쪽'을 먼저 꺼낸다.
    왼쪽 조각은 원래 입력에서 앞쪽에 있던 항목들이라 동점자의 원래 순서가 유지된다.
    (여기를 < 로 바꾸면 불안정 정렬이 된다. 평가에서 묻기 좋은 포인트!)
    """
    merged: list[T] = []
    i = 0  # left에서 다음에 볼 위치
    j = 0  # right에서 다음에 볼 위치

    while i < len(left) and j < len(right):
        if key(left[i]) <= key(right[j]):
            merged.append(left[i])
            i += 1
        else:
            merged.append(right[j])
            j += 1

    # 한쪽이 바닥나면 남은 쪽은 이미 정렬돼 있으니 통째로 뒤에 붙인다
    merged.extend(left[i:])
    merged.extend(right[j:])
    return merged

"""커밋 그래프(DAG)와 그래프 탐색 알고리즘.

그래프 용어 (이 파일을 읽기 위한 최소 지식)
- 노드(점)   : 커밋 하나
- 간선(선)   : 커밋 -> 부모 커밋 연결. commit.parents 에 적혀 있다
- 차수       : 한 노드에 붙은 선의 개수
- DAG        : 방향은 있고(자식 -> 부모), 돌아오는 길(순환)은 없는 그래프

왜 커밋 그래프는 DAG인가?
  커밋은 '이미 존재하는 커밋'만 부모로 가리킬 수 있다.
  부모는 항상 자식보다 먼저 만들어지므로 화살표는 과거 방향으로만 뻗는다.
  그래서 따라가다 제자리로 돌아오는 순환이 생길 수 없다.
  add()가 '부모가 이미 있어야 한다'를 검사하는 것이 이 보장을 코드로 만든 것이다.

이 파일의 알고리즘 3개
  topological_order : 부모가 항상 먼저 나오는 순서 (Kahn 알고리즘)
  ancestors         : 모든 조상 찾기                 (BFS)
  shortest_path     : 두 커밋 사이 최단 경로          (BFS)
셋 모두 시간복잡도 O(V + E)  (V=커밋 수, E=부모 연결 수)
"""

from __future__ import annotations

from .models import Commit


class CommitGraph:
    """커밋 저장소 + 커밋 그래프.

    내부 자료구조
    - _commits  : {hash: Commit}  해시맵(dict). hash로 커밋을 O(1)에 찾는다
    - _children : {hash: [자식 hash...]}  부모->자식 방향 역방향 연결
                  (Commit에는 부모만 적혀 있어서 자식 방향은 따로 기록해 둔다)
    - _order    : 만들어진 순서대로의 hash 목록
    """

    def __init__(self) -> None:
        self._commits: dict[str, Commit] = {}
        self._children: dict[str, list[str]] = {}
        self._order: list[str] = []

    # ------------------------------------------------------------------
    # 저장 / 조회
    # ------------------------------------------------------------------
    def __len__(self) -> int:
        return len(self._commits)

    def __contains__(self, commit_hash: str) -> bool:
        return commit_hash in self._commits

    def get(self, commit_hash: str) -> Commit | None:
        """hash로 커밋을 바로 꺼낸다. 없으면 None. (dict 조회라 평균 O(1))"""
        return self._commits.get(commit_hash)

    def add(self, commit: Commit) -> None:
        """커밋을 그래프에 추가한다.

        검사 두 가지가 DAG를 지켜 준다.
        1) hash 중복 금지 (커밋 hash는 유일해야 한다)
        2) 부모는 반드시 '이미 들어 있는' 커밋이어야 한다 -> 순환 불가능
        """
        if commit.hash in self._commits:
            raise ValueError(f"duplicate commit hash: {commit.hash}")
        if len(set(commit.parents)) != len(commit.parents):
            raise ValueError("duplicate parents")
        for parent in commit.parents:
            if parent not in self._commits:
                raise ValueError(f"unknown parent: {parent}")

        self._commits[commit.hash] = commit
        self._children[commit.hash] = []
        self._order.append(commit.hash)
        for parent in commit.parents:
            self._children[parent].append(commit.hash)

    # ------------------------------------------------------------------
    # 알고리즘 1: 위상 정렬 (LOG)
    # ------------------------------------------------------------------
    def topological_order(self) -> list[str]:
        """부모가 항상 자식보다 먼저 나오도록 모든 커밋 hash를 나열한다. (Kahn 알고리즘)

        핵심 아이디어: '아직 출력 안 된 부모가 0개'인 커밋부터 꺼낸다.
            1) 각 커밋의 "기다리는 부모 수"(진입 차수)를 센다
            2) 기다리는 부모가 0개인 커밋(= 뿌리 커밋)을 큐에 넣는다
            3) 큐에서 하나 꺼내 출력하고, 그 커밋의 자식들의 "기다리는 부모 수"를 1씩 줄인다
            4) 0이 된 자식은 이제 출력해도 되므로 큐에 넣는다
            5) 큐가 빌 때까지 반복
        부모가 2개인 커밋(병합 커밋)은 두 부모가 모두 나온 뒤에야 큐에 들어간다.

        시간복잡도 O(V + E). 순환이 있으면 일부 커밋이 영원히 0이 못 되어 빠지므로
        개수 비교로 순환을 감지할 수 있다(여기서는 일어날 수 없지만 안전장치).
        """
        waiting_parents = {h: len(self._commits[h].parents) for h in self._order}
        queue = [h for h in self._order if waiting_parents[h] == 0]

        front = 0  # 큐의 맨 앞 위치. pop(0)은 느리므로 위치 번호만 앞으로 민다
        while front < len(queue):
            current = queue[front]
            front += 1
            for child in self._children[current]:
                waiting_parents[child] -= 1
                if waiting_parents[child] == 0:
                    queue.append(child)

        if len(queue) != len(self._order):
            raise ValueError("cycle detected: not a DAG")
        return queue

    # ------------------------------------------------------------------
    # 알고리즘 2: 조상 탐색 (ANCESTORS)
    # ------------------------------------------------------------------
    def ancestors(self, commit_hash: str) -> list[str]:
        """commit_hash에서 부모 방향으로 도달 가능한 모든 조상을 가까운 순서로 돌려준다. (BFS)

        부모 -> 부모의 부모 -> ... 를 끝까지 거슬러 올라간다.
        visited(이미 본 커밋 집합)가 꼭 필요하다:
            병합 커밋처럼 같은 조상으로 가는 길이 여러 개일 때 중복 방문/중복 출력을 막는다.
        자기 자신은 조상이 아니므로 결과에 넣지 않는다.
        """
        visited = {commit_hash}
        queue = [commit_hash]
        found: list[str] = []

        front = 0
        while front < len(queue):
            current = queue[front]
            front += 1
            for parent in self._commits[current].parents:
                if parent not in visited:
                    visited.add(parent)
                    queue.append(parent)
                    found.append(parent)
        return found

    # ------------------------------------------------------------------
    # 알고리즘 3: 최단 경로 (PATH)
    # ------------------------------------------------------------------
    def neighbors(self, commit_hash: str) -> list[str]:
        """방향을 무시하고 이 커밋과 선으로 이어진 모든 커밋 = 부모 + 자식.

        PATH는 '부모-자식 연결을 무방향 간선으로 본다'고 정의돼 있다.
        갈라진 두 브랜치의 끝 커밋끼리는 공통 조상까지 내려갔다 올라가야 만나기 때문이다.
        """
        return self._commits[commit_hash].parents + self._children[commit_hash]

    def shortest_path(self, start: str, end: str) -> list[str] | None:
        """start -> end 최단 경로(간선 수 최소)를 돌려준다. 길이 없으면 None.

        최단 경로가 여러 개면 'h1->h2->...' 문자열이 사전순으로 가장 작은 경로를 고른다.

        방법 (2단계)
            1단계: end에서 BFS를 돌려 '모든 커밋의 end까지 거리'를 구한다.
            2단계: start에서 출발해, 매 걸음마다
                   '거리가 정확히 1 작은 이웃' 중 hash가 가장 작은 쪽으로 걷는다.

        왜 이 욕심쟁이(greedy) 선택이 맞나?
            최단 경로는 모두 같은 개수의 커밋을 지난다. 길이가 같은 두 문자열의 사전순 비교는
            '처음으로 달라지는 칸'이 결정하므로, 앞 칸부터 작은 hash를 고르면
            전체 문자열도 가장 작다. ("c1->" 처럼 '-'가 숫자보다 작아서 hash 길이가 달라도 같은 결론)
        시간복잡도 O(V + E).
        """
        distance_to_end = self._distances_from(end)
        if start not in distance_to_end:
            return None

        path = [start]
        current = start
        while current != end:
            best: str | None = None
            for neighbor in self.neighbors(current):
                if distance_to_end.get(neighbor) == distance_to_end[current] - 1:
                    if best is None or neighbor < best:
                        best = neighbor
            # distance_to_end[current] >= 1 이면 거리가 1 작은 이웃이 반드시 하나 이상 있다
            assert best is not None
            path.append(best)
            current = best
        return path

    def _distances_from(self, source: str) -> dict[str, int]:
        """source에서 무방향 BFS를 돌려 {커밋: source까지의 최소 간선 수}를 만든다.

        BFS는 '가까운 곳부터 한 겹씩' 넓혀 가므로 처음 닿은 거리가 곧 최단 거리다.
        source와 이어지지 않은 커밋은 결과에 아예 나오지 않는다.
        """
        distance = {source: 0}
        queue = [source]

        front = 0
        while front < len(queue):
            current = queue[front]
            front += 1
            for neighbor in self.neighbors(current):
                if neighbor not in distance:
                    distance[neighbor] = distance[current] + 1
                    queue.append(neighbor)
        return distance

"""역색인(Inverted Index).

역색인이란?
  책 맨 뒤의 '찾아보기'와 같다. "이 단어는 몇 쪽에 나온다"를 미리 적어 둔 표.
  보통 색인은 '커밋 -> 단어들'이지만, 역색인은 거꾸로 '단어 -> 커밋들'을 저장한다.

  keyword_index = { "login": ["c002", "c005"],  "add": ["c001", "c002"], ... }
  author_index  = { "alice": ["c001", "c002"],  "bob": ["c003"], ... }

왜 빠른가?
  - 순회 검색   : 모든 커밋의 메시지를 하나씩 열어 본다           -> O(N)  (N=전체 커밋 수)
  - 역색인 검색 : 단어로 dict를 한 번 조회하면 후보가 바로 나온다 -> 평균 O(1) + 결과 개수 K
  대신 커밋을 만들 때 표를 갱신하는 일(쓰기 비용)을 조금 더 한다. 읽기를 빠르게 하려고
  쓰기에 비용을 미리 치르는 전형적인 교환(trade-off)이다.
"""

from __future__ import annotations

from .models import Commit


class InvertedIndex:
    """키워드 -> 커밋 목록, 작성자 -> 커밋 목록 두 가지 역색인을 가진다."""

    def __init__(self) -> None:
        self._by_keyword: dict[str, list[str]] = {}
        self._by_author: dict[str, list[str]] = {}

    def add(self, commit: Commit) -> None:
        """커밋 한 개를 두 인덱스에 등록한다. COMMIT 할 때마다 호출된다.

        키워드 추출 규칙(과제 최소 기준): 메시지를 공백으로 split -> 소문자로 lower.
        같은 단어가 한 메시지에 두 번 나와도 그 커밋은 한 번만 등록한다.
        작성자도 소문자로 정규화해서 `--author=alice` 로 "Alice"를 찾을 수 있게 한다.
        """
        self._by_author.setdefault(commit.author.lower(), []).append(commit.hash)

        seen: set[str] = set()
        for token in commit.message.split():
            word = token.lower()
            if word in seen:
                continue
            seen.add(word)
            self._by_keyword.setdefault(word, []).append(commit.hash)

    def search_keyword(self, query: str) -> list[str]:
        """query의 단어를 모두 포함한 커밋 hash 목록(만든 순서).

        단어가 하나면 dict 한 번 조회로 끝난다.
        "add login"처럼 여러 단어면 각 단어의 후보 목록을 교집합(AND)한다.
        """
        words = [token.lower() for token in query.split()]
        if not words:
            return []

        result = self._by_keyword.get(words[0], [])
        for word in words[1:]:
            allowed = set(self._by_keyword.get(word, []))
            result = [h for h in result if h in allowed]
        return list(result)

    def search_author(self, name: str) -> list[str]:
        """해당 작성자가 쓴 커밋 hash 목록(만든 순서)."""
        return list(self._by_author.get(name.strip().lower(), []))

    def dump(self) -> list[str]:
        """인덱스 내용을 사람이 볼 수 있는 줄 목록으로 만든다 (INDEX 명령, 시연/디버깅용)."""
        lines = ["[keyword index]"]
        for word, hashes in self._by_keyword.items():
            lines.append(f"  {word} -> {', '.join(hashes)}")
        lines.append("[author index]")
        for name, hashes in self._by_author.items():
            lines.append(f"  {name} -> {', '.join(hashes)}")
        return lines

(문자열로 예쁘게 바꾸는 일은 cli.py가 한다 -> 로직과 화면의 분리)

Git 개념 3가지
- 브랜치 : 커밋 하나를 가리키는 이름표.  {"main": "c003", "feature": "c002"}
- HEAD   : '지금 올라타 있는 브랜치'를 가리키는 포인터.
- 커밋   : 현재 브랜치가 가리키는 커밋을 부모로 삼아 새 커밋을 만들고, 이름표를 새 커밋으로 옮긴다.
"""

from __future__ import annotations

from datetime import datetime
from typing import Callable

from .graph import CommitGraph
from .index import InvertedIndex
from .models import Commit, HashGenerator, MiniGitError
from .sorting import merge_sort


def _now() -> datetime:
    """현재 시각(초 단위). 테스트에서는 가짜 시계로 바꿔 끼울 수 있다."""
    return datetime.now().replace(microsecond=0)


class Repository:
    """Mini Git 저장소 한 개."""

    def __init__(self, clock: Callable[[], datetime] | None = None) -> None:
        self._clock = clock or _now
        # hash 발급기는 INIT을 다시 해도 유지한다 -> hash가 세션 내내 유일하다
        self._hashes = HashGenerator()
        self._reset()

    def _reset(self) -> None:
        """저장소를 빈 상태로 되돌린다 (INIT 때 사용)."""
        self.initialized = False
        self.author = ""
        self.head = ""  # 현재 브랜치 이름
        self.branches: dict[str, str | None] = {}  # 브랜치 이름 -> 커밋 hash (첫 커밋 전엔 None)
        self.graph = CommitGraph()
        self.index = InvertedIndex()

    # ------------------------------------------------------------------
    # 저장소 / 브랜치 관리
    # ------------------------------------------------------------------
    def init(self, user_name: str) -> None:
        """INIT: 저장소 초기화. main 브랜치를 만들고 HEAD를 main으로, 작성자를 설정한다."""
        user_name = user_name.strip()
        if not user_name:
            raise MiniGitError("Invalid args")

        self._reset()
        self.initialized = True
        self.author = user_name
        self.head = "main"
        self.branches["main"] = None  # 아직 커밋이 없으므로 가리키는 곳이 없다

    def set_user(self, user_name: str) -> None:
        """USER: (보조 명령) 저장소는 그대로 두고 앞으로 만들 커밋의 작성자만 바꾼다.

        INIT은 저장소를 통째로 초기화하므로, 한 저장소에서 여러 사람의 커밋을 만들어
        작성자 검색/정렬을 보여 주려면 이 명령이 필요하다. (git config user.name 과 같은 역할)
        """
        self.require_init()
        user_name = user_name.strip()
        if not user_name:
            raise MiniGitError("Invalid args")
        self.author = user_name

    def create_branch(self, name: str) -> None:
        """BRANCH: 현재 HEAD가 가리키는 커밋에 새 이름표를 하나 더 단다.

        커밋을 복사하는 게 아니다. 같은 커밋을 가리키는 이름표가 하나 늘 뿐이다.
        첫 커밋 전에 만든 브랜치는 가리키는 곳이 None이고, 거기서 한 첫 커밋은 부모가 없다.
        (그래서 뿌리가 2개인 그래프도 만들 수 있고, 그때 PATH가 'No path'가 된다.)
        """
        self.require_init()
        if not name.strip():
            raise MiniGitError("Invalid args")
        if name in self.branches:
            raise MiniGitError(f"Branch already exists: {name}")
        self.branches[name] = self.branches[self.head]

    def switch(self, name: str) -> None:
        """SWITCH: HEAD를 다른 브랜치로 옮긴다. 커밋 데이터는 바뀌지 않는다."""
        self.require_init()
        if name not in self.branches:
            raise MiniGitError(f"Unknown branch: {name}")
        self.head = name

    def commit(self, message: str) -> Commit:
        """COMMIT: 현재 브랜치 끝을 부모로 하는 새 커밋을 만든다.

        순서
            1) 새 hash 발급, 부모 = 현재 브랜치가 가리키는 커밋 (없으면 부모 없음)
            2) 그래프(해시맵)에 저장
            3) 현재 브랜치 이름표를 새 커밋으로 이동
            4) 역색인(author / keyword) 갱신
        """
        self.require_init()
        if not message.strip():
            raise MiniGitError("Invalid args")

        tip = self.branches[self.head]
        commit = Commit(
            hash=self._hashes.next_hash(),
            message=message,
            author=self.author,
            timestamp=self._clock(),
            parents=[] if tip is None else [tip],
        )
        self.graph.add(commit)
        self.branches[self.head] = commit.hash
        self.index.add(commit)
        return commit

    # ------------------------------------------------------------------
    # 조회: 로그 / 탐색 / 검색
    # ------------------------------------------------------------------
    def log(self, sort_by: str | None = None) -> list[Commit]:
        """LOG: 커밋 목록.

        - 옵션 없음     : 위상 정렬 순서. 부모가 항상 자식보다 먼저 나온다.
        - sort_by=date  : timestamp 오름차순(오래된 것 먼저)
        - sort_by=author: 작성자 이름 오름차순(대소문자 무시)
        동률이면 '위상 정렬 순서'가 유지된다(병합 정렬이 안정 정렬이기 때문).
        """
        self.require_init()
        commits = [self.graph.get(h) for h in self.graph.topological_order()]

        if sort_by is None:
            return commits
        if sort_by == "date":
            return merge_sort(commits, key=lambda c: c.timestamp)
        if sort_by == "author":
            return merge_sort(commits, key=lambda c: c.author.lower())
        raise MiniGitError("Invalid args")

    def branch_labels(self) -> dict[str, list[str]]:
        """{커밋 hash: ["HEAD -> main", "feature"]}  로그에 붙일 브랜치 표시를 만든다."""
        labels: dict[str, list[str]] = {}
        for name, tip in self.branches.items():
            if tip is None:
                continue
            if name == self.head:
                labels.setdefault(tip, []).insert(0, f"HEAD -> {name}")  # 현재 브랜치는 맨 앞에
            else:
                labels.setdefault(tip, []).append(name)
        return labels

    def path(self, first: str, second: str) -> list[str] | None:
        """PATH: 두 커밋 사이 최단 경로. 길이 없으면 None."""
        self.require_init()
        start = self._resolve(first)
        end = self._resolve(second)
        return self.graph.shortest_path(start, end)

    def ancestors(self, commit_hash: str) -> list[Commit]:
        """ANCESTORS: 모든 조상 커밋(가까운 조상부터)."""
        self.require_init()
        target = self._resolve(commit_hash)
        return [self.graph.get(h) for h in self.graph.ancestors(target)]

    def search_keyword(self, keyword: str) -> list[Commit]:
        """SEARCH <keyword>: 역색인으로 후보를 바로 가져온다 (전체 순회 없음)."""
        self.require_init()
        if not keyword.strip():
            raise MiniGitError("Invalid args")
        return [self.graph.get(h) for h in self.index.search_keyword(keyword)]

    def search_author(self, name: str) -> list[Commit]:
        """SEARCH --author=<name>: 작성자 역색인 조회."""
        self.require_init()
        if not name.strip():
            raise MiniGitError("Invalid args")
        return [self.graph.get(h) for h in self.index.search_author(name)]

    # ------------------------------------------------------------------
    # 내부 도우미
    # ------------------------------------------------------------------
    def require_init(self) -> None:
        """INIT 전에는 다른 명령을 막는 공통 관문."""
        if not self.initialized:
            raise MiniGitError("Repository not initialized. Run INIT <user_name> first")

    def _resolve(self, commit_hash: str) -> str:
        """입력받은 hash를 확인한다. 없는 커밋이면 'Unknown commit: <입력>'.

        hash는 소문자로 발급되므로 입력은 대소문자를 가리지 않게 소문자로 맞춰 비교한다.
        """
        normalized = commit_hash.strip().lower()
        if normalized not in self.graph:
            raise MiniGitError(f"Unknown commit: {commit_hash}")
        return normalized

역할 분담
- 이 파일  : 문자열을 해석하고(파싱), 결과를 보기 좋은 문장으로 바꾼다(출력 형식)
- Repository: 실제 일을 한다. 잘못된 입력이면 MiniGitError를 던진다

흐름:  "COMMIT \"Add login\""  ->  tokenize  ->  ["COMMIT", "Add login"]
        -> 명령 이름 대문자 변환 -> 핸들러 함수 호출 -> 출력할 줄 목록 반환
"""

from __future__ import annotations

import shlex
from typing import Callable

from .models import Commit, MiniGitError
from .repository import Repository

PROMPT = "mini-git> "
TIME_FORMAT = "%Y-%m-%d %H:%M:%S"

HELP_LINES = [
    "Commands (case-insensitive; quote arguments that contain spaces):",
    '  INIT <user_name>                 e.g. INIT "Alice"',
    "  BRANCH <branch_name>             create a branch at HEAD",
    "  SWITCH <branch_name>             move HEAD to a branch",
    '  COMMIT <message>                 e.g. COMMIT "Add login feature"',
    "  LOG [--sort-by=date|author]      parents first (topological) unless sorted",
    "  PATH <commit1> <commit2>         shortest path (parent/child links are undirected)",
    "  ANCESTORS <commit_hash>          every ancestor of a commit",
    '  SEARCH <keyword>                 e.g. SEARCH "login"',
    "  SEARCH --author=<name>           commits written by <name>",
    "  USER <name>                      (extra) change the author without resetting the repo",
    "  INDEX                            show the inverted indexes (debug)",
    "  STATUS                           show user / branch / HEAD",
    "  HELP, EXIT (or QUIT)",
]


# ----------------------------------------------------------------------
# 1) 파싱
# ----------------------------------------------------------------------
def tokenize(line: str) -> list[str]:
    """한 줄을 '단어 목록'으로 자른다. 따옴표로 감싼 부분은 한 덩어리로 취급한다.

    COMMIT "Add login feature"  ->  ["COMMIT", "Add login feature"]
    따옴표를 열고 닫지 않으면 Invalid args.
    """
    try:
        return shlex.split(line)
    except ValueError:
        raise MiniGitError("Invalid args") from None


def _expect(args: list[str], count: int) -> None:
    """인자 개수가 정확히 count개인지 확인한다. 아니면 Invalid args."""
    if len(args) != count:
        raise MiniGitError("Invalid args")


# ----------------------------------------------------------------------
# 2) 출력 형식
# ----------------------------------------------------------------------
def format_log_entry(commit: Commit, labels: list[str]) -> list[str]:
    """LOG 한 항목 = 3줄.  hash / author / timestamp / message 가 모두 보인다."""
    when = commit.timestamp.strftime(TIME_FORMAT)
    tag = f" [{', '.join(labels)}]" if labels else ""
    parents = ", ".join(commit.parents) if commit.parents else "-"
    return [
        f"commit {commit.hash} ({commit.author}, {when}){tag}",
        f"    parents: {parents}",
        f"    {commit.message}",
    ]


def format_commit_list(header: str, commits: list[Commit]) -> list[str]:
    """검색/조상 결과처럼 '한 줄 목록' 형식. 예) - c002: Add login feature (Alice)"""
    lines = [header]
    for commit in commits:
        lines.append(f"- {commit.hash}: {commit.message} ({commit.author})")
    return lines


def _plural(count: int) -> str:
    return "commit" if count == 1 else "commits"


# ----------------------------------------------------------------------
# 3) 명령 핸들러: (저장소, 인자들) -> 출력할 줄 목록
# ----------------------------------------------------------------------
def _cmd_init(repo: Repository, args: list[str]) -> list[str]:
    _expect(args, 1)
    repo.init(args[0])
    return ["Initialized repository.", f"Current branch: {repo.head}", f"Current user: {repo.author}"]


def _cmd_user(repo: Repository, args: list[str]) -> list[str]:
    _expect(args, 1)
    repo.set_user(args[0])
    return [f"Current user: {repo.author}"]


def _cmd_branch(repo: Repository, args: list[str]) -> list[str]:
    _expect(args, 1)
    repo.create_branch(args[0])
    return [f"Created branch: {args[0]}"]


def _cmd_switch(repo: Repository, args: list[str]) -> list[str]:
    _expect(args, 1)
    repo.switch(args[0])
    return [f"Switched to branch: {args[0]}"]


def _cmd_commit(repo: Repository, args: list[str]) -> list[str]:
    _expect(args, 1)
    commit = repo.commit(args[0])
    return [f"[{repo.head} {commit.hash}] {commit.message}"]


def _cmd_log(repo: Repository, args: list[str]) -> list[str]:
    sort_by = None
    if len(args) == 1 and args[0].lower().startswith("--sort-by="):
        sort_by = args[0].split("=", 1)[1].lower()
    elif args:
        raise MiniGitError("Invalid args")

    commits = repo.log(sort_by)
    if not commits:
        return ["No commits yet"]

    labels = repo.branch_labels()
    lines: list[str] = []
    for commit in commits:
        lines.extend(format_log_entry(commit, labels.get(commit.hash, [])))
    return lines


def _cmd_path(repo: Repository, args: list[str]) -> list[str]:
    _expect(args, 2)
    path = repo.path(args[0], args[1])
    if path is None:
        return ["No path"]
    return ["Path: " + " -> ".join(path)]


def _cmd_ancestors(repo: Repository, args: list[str]) -> list[str]:
    _expect(args, 1)
    found = repo.ancestors(args[0])
    if not found:
        return ["No ancestors"]
    return format_commit_list(f"Ancestors of {args[0].lower()} ({len(found)}):", found)


def _cmd_search(repo: Repository, args: list[str]) -> list[str]:
    _expect(args, 1)
    query = args[0]
    if query.lower().startswith("--author="):
        found = repo.search_author(query.split("=", 1)[1])
    elif query.startswith("--"):
        raise MiniGitError("Invalid args")  # 모르는 옵션
    else:
        found = repo.search_keyword(query)

    if not found:
        return ["No commits found"]
    return format_commit_list(f"Found {len(found)} {_plural(len(found))}:", found)


def _cmd_index(repo: Repository, args: list[str]) -> list[str]:
    _expect(args, 0)
    repo.require_init()
    return repo.index.dump()


def _cmd_status(repo: Repository, args: list[str]) -> list[str]:
    _expect(args, 0)
    repo.require_init()
    tip = repo.branches[repo.head] or "(no commits yet)"
    return [f"User: {repo.author}", f"Current branch: {repo.head}", f"HEAD commit: {tip}",
            f"Branches: {', '.join(repo.branches)}", f"Total commits: {len(repo.graph)}"]


def _cmd_help(repo: Repository, args: list[str]) -> list[str]:
    return list(HELP_LINES)


Handler = Callable[[Repository, list[str]], list[str]]

# 명령 이름 -> 처리 함수.  새 명령은 여기에 한 줄 추가하면 된다.
COMMANDS: dict[str, Handler] = {
    "INIT": _cmd_init,
    "USER": _cmd_user,
    "BRANCH": _cmd_branch,
    "SWITCH": _cmd_switch,
    "COMMIT": _cmd_commit,
    "LOG": _cmd_log,
    "PATH": _cmd_path,
    "ANCESTORS": _cmd_ancestors,
    "SEARCH": _cmd_search,
    "INDEX": _cmd_index,
    "STATUS": _cmd_status,
    "HELP": _cmd_help,
}


# ----------------------------------------------------------------------
# 4) 실행 / REPL
# ----------------------------------------------------------------------
def execute(repo: Repository, line: str) -> list[str] | None:
    """한 줄을 실행하고 출력할 줄 목록을 돌려준다. EXIT/QUIT이면 None(= 종료 신호).

    MiniGitError는 여기서 잡아서 '에러 문장 한 줄'로 바꾼다. 프로그램은 죽지 않는다.
    """
    try:
        tokens = tokenize(line)
        if not tokens:
            return []  # 빈 줄은 무시

        name = tokens[0].upper()  # 명령어는 대소문자 구분 없음
        if name in ("EXIT", "QUIT"):
            return None
        handler = COMMANDS.get(name)
        if handler is None:
            return [f"Unknown command: {tokens[0]}"]
        return handler(repo, tokens[1:])
    except MiniGitError as error:
        return [str(error)]


def run_repl(repo: Repository | None = None,
             read: Callable[[str], str] = input,
             write: Callable[[str], None] = print) -> None:
    """프롬프트를 띄우고 명령을 계속 받는 반복문 (Read-Eval-Print Loop).

    저장소는 한 번만 만들어 계속 쓰므로 앞에서 만든 커밋/브랜치가 유지된다.
    EXIT, QUIT, Ctrl+D(EOF), Ctrl+C 모두 조용히 종료한다.
    read/write를 바꿔 끼울 수 있게 해 둔 것은 테스트를 쉽게 하기 위해서다.
    """
    repo = repo or Repository()
    write("Mini Git - type HELP for commands, EXIT to quit.")

    while True:
        try:
            line = read(PROMPT)
        except (EOFError, KeyboardInterrupt):
            write("")
            return

        output = execute(repo, line)
        if output is None:
            return
        for text in output:
            write(text)

def fake_clock(step_seconds=60):
    """호출할 때마다 step_seconds씩 흐르는 가짜 시계 (테스트 결과를 고정하기 위해)."""
    state = {"now": datetime(2024, 1, 15, 9, 0, 0) - timedelta(seconds=step_seconds)}

    def tick():
        state["now"] += timedelta(seconds=step_seconds)
        return state["now"]

    return tick


def run(repo, *lines):
    """여러 줄을 차례로 실행하고 마지막 줄의 출력을 돌려준다."""
    output = None
    for line in lines:

    return output


def make_commit(name, parents, when=None):
    return Commit(hash=name, message=f"msg {name}", author="a",
                  timestamp=when or datetime(2024, 1, 1), parents=list(parents))


def random_dag(rng, size, max_parents=3, root_chance=0.15):
    """임의의 DAG. 각 노드의 부모는 '앞에 만든 노드' 중에서만 고른다. 뿌리가 여러 개일 수 있다."""
    graph = CommitGraph()
    names = []
    for i in range(size):
        name = f"n{i:02d}"
        parents = []
        if names and rng.random() > root_chance:
            for candidate in rng.sample(names, min(len(names), rng.randint(1, max_parents))):
                parents.append(candidate)
        graph.add(make_commit(name, parents))
        names.append(name)
    return graph, names


def all_simple_paths(graph, start, end):
    """(검증용) 무방향 그래프에서 start->end 모든 단순 경로를 DFS로 전부 나열한다."""
    results = []

    def walk(current, path):
        if current == end:
            results.append(list(path))
            return
        for neighbor in graph.neighbors(current):
            if neighbor not in path:
                path.append(neighbor)
                walk(neighbor, path)
                path.pop()

    walk(start, [start])
    return results


def expected_shortest(graph, start, end):
    """(검증용) 문제 정의 그대로: 최단 길이 중 'a->b->c' 문자열이 가장 작은 경로."""
    best = None
    for path in all_simple_paths(graph, start, end):
        text = "->".join(path)
        if best is None or len(path) < len(best[1]) or (len(path) == len(best[1]) and text < best[0]):
            best = (text, path)
    return None if best is None else best[1]


def reachable_parents(graph, name):
    """(검증용) 재귀로 구한 모든 조상 집합."""
    seen = set()

    def visit(h):
        for parent in graph.get(h).parents:
            if parent not in seen:
                seen.add(parent)
                visit(parent)

    visit(name)
    return seen

# Mini Git

Git의 핵심 구조(커밋 그래프, 브랜치, 검색 인덱스, 정렬)를 Python으로 직접 구현한 **CLI 기반 Mini Git**입니다.
실제 `git` 명령이나 그래프 라이브러리를 쓰지 않고, 모든 알고리즘(위상 정렬, BFS, 역색인, 병합 정렬)을 손으로 만들었습니다.
데이터는 메모리에만 저장되며 프로그램을 끝내면 사라집니다.

## 실행

- Python 3.10 이상 (외부 라이브러리 없음)

```console
python main.py
```

`mini-git>` 프롬프트에 명령을 입력합니다. `exit` 또는 `quit`으로 종료합니다.
테스트는 `python -m unittest -v` 로 실행합니다 (41개).

## 명령어

명령어는 **대소문자를 구분하지 않습니다**(`INIT`, `init` 모두 가능). 공백이 들어간 인자는 **따옴표**로 감쌉니다.

| 명령 | 설명 |
| --- | --- |
| `INIT <user_name>` | 저장소 초기화. `main` 브랜치 생성, HEAD를 `main`으로, 작성자 설정 |
| `BRANCH <branch_name>` | 현재 HEAD가 가리키는 커밋에 새 브랜치 생성 |

의존 방향은 한 줄입니다: `cli` → `repository` → (`graph` / `index` / `sorting` / `models`). 알고리즘(탐색·정렬·인덱싱)은 각각 독립된 클래스/함수이며 주요 함수에 docstring이 있습니다.

## 설계와 알고리즘

| 기능 | 알고리즘 | 시간복잡도 (V=커밋 수, E=부모 연결 수) |
| --- | --- | --- |
| `LOG` | 위상 정렬 (Kahn 알고리즘) | O(V + E) |
| `LOG --sort-by=…` | 병합 정렬 (안정) | 평균·최악 모두 O(V log V), 추가 메모리 O(V) |
| `PATH` | 무방향 BFS + 사전순 욕심쟁이 경로 복원 | O(V + E) |
| `ANCESTORS` | 부모 방향 BFS (visited 집합) | O(V + E) |
| `SEARCH` | 역색인 dict 조회 | 평균 O(1) + 결과 개수 (순회 검색은 O(V)) |
| 커밋 조회 | 해시맵(dict) | 평균 O(1) |

- **DAG**: 커밋은 *이미 존재하는* 커밋만 부모로 가질 수 있습니다(`CommitGraph.add`가 검사). 부모는 항상 자식보다 먼저 만들어지므로 순환이 생길 수 없습니다.
- **위상 정렬(LOG)**: "아직 출력되지 않은 부모가 0개"인 커밋부터 꺼내 출력하고, 그 자식들의 대기 부모 수를 1씩 줄입니다. 부모가 둘인 병합 커밋도 두 부모가 모두 나온 뒤에 출력됩니다.
- **최단 경로(PATH)**: 부모-자식 연결을 방향 없는 간선으로 봅니다. 도착점에서 BFS로 모든 커밋의 거리를 구한 뒤, 출발점에서 "거리가 1 작은 이웃 중 hash가 가장 작은 쪽"으로 걸어가면 `h1->h2->…` 문자열이 사전순으로 가장 작은 최단 경로가 됩니다(최단 경로는 모두 같은 개수의 커밋을 지나므로 앞 칸부터 작은 것을 고르면 전체가 최소).
- **역색인**: 커밋할 때 메시지를 `split()` 후 `lower()`한 단어마다 `keyword -> hash 목록`에, 작성자(소문자)는 `author -> hash 목록`에 등록합니다. 검색은 모든 커밋을 훑지 않고 dict에서 후보를 바로 꺼냅니다.
- **정렬**: `sorted()` / `list.sort()`를 쓰지 않고 병합 정렬을 직접 구현했습니다. 합칠 때 키가 같으면 왼쪽을 먼저 꺼내 **안정 정렬**이 되므로, 동률(예: 같은 초에 만든 커밋)은 위상 정렬 순서(부모 먼저)가 유지됩니다.

## 과제 목표 점검

1. **커밋 그래프와 DAG** — 커밋 = 노드, `parents` = 간선. 새 커밋은 기존 커밋만 가리키므로 방향은 있고(자식→부모) 순환은 없습니다.
2. **부모 먼저 출력되는 로그** — 단순 최신순이 아니라 위상 정렬(Kahn)이 필요합니다. 브랜치가 갈라진 그래프에서도 부모→자식 순서가 깨지지 않습니다.
3. **최단 경로 / 조상 탐색** — 둘 다 BFS. PATH는 부모+자식(무방향) 이웃으로, ANCESTORS는 부모 방향으로만 진행하며 visited로 중복을 막습니다.
4. **정렬** — 병합 정렬: 평균/최악 O(n log n), 안정 정렬. `key` 함수만 바꿔 날짜순/작성자순을 모두 처리합니다.
5. **역색인** — "단어 → 커밋 목록"을 미리 만들어 두므로 검색이 평균 O(1)에 후보를 얻습니다. 대신 COMMIT 때 인덱스를 갱신하는 비용을 치릅니다.

## 구현 선택과 한계

- **hash**: 증가 카운터(`c001`, `c002`, …). 카운터는 줄지 않으므로 세션 내 중복이 불가능하고, `INIT`을 다시 해도 발급기는 유지됩니다. (실제 Git은 내용 기반 SHA-1을 씁니다.) 입력할 때 hash의 대소문자는 구분하지 않습니다.
- **키워드 규칙**: 최소 기준 그대로 `split` + `lower`만 적용합니다. 구두점은 떼지 않으므로 메시지 `Fix bug: login`의 키워드는 `bug:`이고 `bug`로는 검색되지 않습니다.
- **작성자 검색**은 대소문자를 구분하지 않습니다 (`--author=alice` 로 `Alice`를 찾음).
- **첫 커밋 전에 만든 브랜치**는 가리키는 커밋이 아직 없고, 거기서 한 첫 커밋은 부모가 없는 뿌리 커밋이 됩니다. 뿌리가 2개면 서로 이어지지 않아 `PATH`가 `No path`를 출력합니다.
- 동률 규칙: `--sort-by` 결과에서 키가 같으면 위상 정렬(LOG) 순서를 유지합니다.
- 파일 내용 추적, 네트워크, 파일 저장(영속성)은 구현하지 않았습니다. 보너스 과제(diff / merge / 정렬 성능 비교)는 포함하지 않았습니다.

6-2. 과제 목표 5개 — 30초 답변

과제 원문의 "이 과제를 마친 후, 학습자는 아래를 스스로 설명할 수 있어야 한다" 5항목입니다. 각 항목: ① 30초 대본 → ② 한 단계 더 → ③ 코드로 보여주기 → ④ 꼬리질문.

목표 1. "커밋 그래프를 구현하고, Git의 커밋 구조가 왜 DAG인지 설명할 수 있다."

30초 대본

"Git의 커밋은 그래프의 점이고, 커밋이 자기 부모를 가리키는 화살표가 선입니다. 화살표에 방향이 있으니 방향 그래프이고, 따라가다 출발점으로 돌아오는 순환이 없어서 DAG 입니다. 순환이 없는 이유는 새 커밋은 이미 존재하는 커밋만 부모로 삼을 수 있어서 화살표가 항상 과거로만 향하기 때문입니다. 제 코드에서는 CommitGraph.add 가 부모가 이미 저장돼 있는지 검사해서 이걸 강제합니다. 그냥 트리가 아니라 DAG 인 이유는 병합 커밋처럼 부모가 둘일 수 있기 때문이고, 저는 parents 를 리스트로 만들어 그걸 지원합니다."

한 단계 더: 커밋 저장소는 {hash: Commit} dict(해시맵)라 hash 로 평균 O(1) 조회, 부모→자식 방향은 _children 에 따로 기록합니다. 첫 커밋은 부모 0개(뿌리).

코드로 보여주기: graph.py 의 add 메서드 (검사 3개) → models.py 의 Commit 필드 5개. 시연의 log 출력에서 parents: 줄을 가리키면 "이게 화살표"라고 말할 수 있습니다.

꼬리질문: 순환이 생기면 어떻게 되나요?

정상 흐름에서는 생길 수 없게 add 가 막습니다. 만약 어떤 이유로 생기더라도 위상 정렬(Kahn)에서 일부 커밋이 영원히 대기 수 0이 못 돼 출력 개수가 모자라므로 cycle detected 로 감지합니다.

꼬리질문: 왜 그냥 리스트(한 줄)가 아니고 그래프인가요?

브랜치가 갈라지면 같은 부모를 가진 커밋이 둘 생깁니다(형제). 한 줄 리스트로는 표현할 수 없습니다.

목표 2. "'부모가 먼저 출력되는 로그'를 만들기 위해 어떤 접근(위상 정렬 성격)이 필요한지 설명할 수 있다."

30초 대본

"기본 LOG 는 최신순이 아니라 부모가 항상 자식보다 먼저 나와야 합니다. 이건 선수과목을 먼저 듣는 순서와 같은 위상 정렬 문제입니다. 저는 Kahn 알고리즘을 썼습니다. 각 커밋에 '아직 출력 안 된 부모 수'를 적어 두고, 0인 커밋부터 꺼내 출력합니다. 꺼낸 커밋의 자식들은 숫자를 1씩 줄이고 0이 되면 큐에 넣습니다. 그래서 부모가 둘인 병합 커밋도 두 부모가 다 나온 뒤에야 출력됩니다. 시간은 커밋 수 V, 연결 수 E 에 대해 O(V+E) 입니다."

한 단계 더: 위상 정렬 결과는 하나로 정해지지 않습니다(갈라진 두 가지 중 누가 먼저여도 됨). 제 구현은 뿌리와 자식을 만든 순서대로 넣어서 항상 같은 결과가 나옵니다.

코드로 보여주기: graph.py → topological_order 의 8줄. 3장 위상 정렬 시각화(병합 그래프 탭)를 떠올리며 "m 은 b, c 둘 다 나올 때까지 기다린다"를 설명.

★ 꼬리질문: 그냥 만든 순서대로 출력해도 부모가 먼저 아닌가요? (정직하게)

맞습니다. 이 프로그램에서는 만든 순서도 유효한 위상 순서입니다(부모는 항상 먼저 만들어지므로). 하지만 그건 "저장 순서에 기대는" 방법이고, Kahn 은 그래프 구조만으로 부모 먼저를 보장합니다 — 예를 들어 커밋이 임의 순서로 들어오거나 병합 커밋이 있어도 성립합니다. 과제가 "위상 정렬 성격의 출력"을 학습 목표로 제시해서 Kahn 으로 구현했습니다. (실제로 시연에서 c005 가 c004 보다 먼저 나오는 것이 "만든 순서"와 "위상 정렬 순서"가 다르다는 증거입니다.)

꼬리질문: DFS 로도 위상 정렬이 되나요?

됩니다 (DFS 완료 순서를 뒤집기). 저는 "기다리는 부모 수"로 직관적으로 설명되고 순환 감지가 쉬운 Kahn 을 골랐습니다. 복잡도는 둘 다 O(V+E).

목표 3. "두 커밋 사이의 최단 경로를 찾는 방법과 특정 커밋의 모든 조상을 탐색하는 방법을 설명할 수 있다."

30초 대본

"PATH 는 부모-자식 연결을 방향 없는 선으로 보고 BFS 로 풉니다. BFS 는 가까운 곳부터 퍼지기 때문에 처음 도착한 거리가 곧 최단이라 간선 수 최소가 보장됩니다. 동률 경로 중 사전순 최소는, 도착점에서 BFS 로 거리표를 만든 뒤 출발점에서 걸으면서 거리가 1 작은 이웃 중 hash 가 가장 작은 쪽을 고르는 방식으로 얻습니다. ANCESTORS 는 같은 BFS 를 부모 방향으로만 하고 visited 로 중복을 막아 모든 조상을 빠짐없이 찾습니다. 둘 다 O(V+E) 입니다."

한 단계 더: 방향을 무시해야 하는 이유 = 갈라진 두 브랜치 끝은 공통 조상까지 내려갔다 올라가야 만나기 때문. 경로가 없으면 None → No path.

코드로 보여주기: graph.py 의 _distances_from(BFS) → shortest_path(걷기) → ancestors. 시연 ⑥, 3장 BFS 시각화의 "병합 그래프 · PATH a m" 탭(후보 b, c 중 b 선택)이 가장 설득력 있습니다.

★ 꼬리질문: 왜 도착점에서 BFS 를 시작하나요?

시작점에서 BFS 를 하면 "먼저 도착한 부모" 하나만 기억하게 되어 동률 경로 중 사전순 최소를 고르기 어렵습니다(모든 최단 경로를 저장해야 함). 도착점 기준 거리표가 있으면 출발점에서 한 걸음씩 거리를 줄이며 매번 가장 작은 hash 를 고르기만 하면 됩니다.

꼬리질문: 왜 DFS 가 아니라 BFS 인가요?

DFS 는 한 길로 끝까지 가므로 처음 찾은 경로가 최단이라는 보장이 없습니다. 가중치 없는 그래프의 최단 경로는 BFS 의 정석입니다.

꼬리질문: visited 가 없으면 ANCESTORS 가 어떻게 되나요?

DAG 라 무한 루프는 아니지만, 병합 커밋처럼 같은 조상에 이르는 길이 여러 개면 같은 조상을 중복 방문·중복 출력합니다(다이아몬드가 연쇄되면 경우의 수가 지수로 늘 수도 있음). visited 집합이 이를 막습니다.

목표 4. "정렬 알고리즘을 직접 구현하고, 평균/최악 시간복잡도 및 안정 정렬 여부를 설명할 수 있다."

30초 대본

"sorted 를 못 쓰니 병합 정렬을 직접 구현했습니다. 리스트를 반으로 쪼개 각각 정렬하고, 정렬된 두 조각을 맨 앞끼리 비교하며 합칩니다. 평균·최악 모두 O(n log n) 이고, 합칠 때 새 리스트가 필요해서 메모리는 O(n) 입니다. 키가 같으면 왼쪽을 먼저 꺼내기 때문에 안정 정렬입니다. 그래서 같은 작성자·같은 시각의 커밋은 원래 부모 먼저 순서가 유지됩니다. 비교 기준은 key 함수로 갈아 끼워서 날짜순과 작성자순을 같은 코드로 처리합니다."

한 단계 더: O(n log n) 인 이유 — 쪼개는 깊이가 log₂n 층이고 각 층에서 합치는 양이 n. 퀵 정렬은 평균은 빠르지만 최악 O(n²)·불안정이라 성능 보장과 안정성이 필요한 로그엔 병합 정렬을 골랐습니다.

코드로 보여주기: sorting.py 의 _merge 안 key(left[i]) <= key(right[j]) 줄. "여기가 < 면 불안정해진다"고 짚으면 이해도가 확실히 드러납니다. 시연 ⑧.

꼬리질문: 입력이 이미 정렬돼 있거나 역순이면 더 빠른가요?

병합 정렬은 입력 모양과 상관없이 항상 O(n log n) 입니다(그래서 최악도 같음). 삽입 정렬은 거의 정렬된 입력에 O(n)에 가깝게 빠를 수 있지만 최악은 O(n²).

꼬리질문: 재귀 깊이는 문제 없나요?

절반씩 쪼개므로 깊이는 log₂n 입니다. 커밋이 100만 개여도 약 20단계라 파이썬 재귀 한도(기본 1000)에 걸리지 않습니다.

꼬리질문: 동률일 때 규칙은?

과제는 "동률 처리 규칙은 자유"입니다. 저는 안정 정렬을 이용해 입력 순서(= 위상 정렬 순서)를 유지합니다. 작성자 비교는 대소문자를 무시합니다(lower()).

목표 5. "역색인의 동작 원리와, 순회 검색보다 빠른 이유를 시간복잡도 관점에서 설명할 수 있다."

30초 대본

"역색인은 책 뒤의 찾아보기처럼 '단어 → 커밋 목록'을 미리 만들어 두는 표입니다. COMMIT 할 때 메시지를 공백으로 쪼개 소문자로 바꾼 단어마다, 그리고 작성자마다 커밋 hash 를 등록합니다. 검색할 때는 모든 커밋을 훑지 않고 딕셔너리를 한 번 조회하면 후보가 바로 나와서 평균 O(1) + 결과 개수만큼만 일합니다. 순회 검색은 커밋 수 N 에 비례하는 O(N) 입니다. 대신 커밋할 때 인덱스를 갱신하는 비용과 메모리가 듭니다."

한 단계 더: 읽기를 빠르게 하려고 쓰기 시점에 미리 일해 두는 교환(trade-off). 커밋은 한 번 만들면 바뀌지 않으니(수정·삭제 없음) 인덱스 유지가 쉽습니다.

코드로 보여주기: index.py 의 add, search_keyword + 시연 ⑦의 index 명령 출력. 3장 역색인 위젯의 "순회 vs 역색인" 비교.

꼬리질문: 키워드는 어떻게 추출하나요? 한계는?

과제 최소 기준 그대로 공백 split + lower 입니다. 한계로 구두점이 안 떼져서 Fix bug: login 의 키워드는 bug: 입니다. 개선하려면 strip(".,!?:;") 를 저장·검색에 똑같이 적용하면 됩니다(6-4 참고).

꼬리질문: "add login" 처럼 여러 단어는요?

각 단어의 후보 목록을 구해서 교집합(AND) 합니다. 집합에서 "있나?"는 평균 O(1) 이라 후보 길이에 비례해 끝납니다.

구조 · 설계

★전체 구조를 1분 안에 설명해 주세요.

"cli.py 가 입력을 해석하고 출력 문장을 만들고, repository.py 가 브랜치·HEAD·작성자를 관리하며 부품을 지휘합니다. 실제 알고리즘은 graph.py(위상 정렬·BFS), index.py(역색인), sorting.py(병합 정렬)로 독립돼 있습니다. 의존 방향은 위에서 아래 한 방향입니다."

왜 이렇게 파일을 나눴나요?

과제가 알고리즘 로직을 독립된 함수·클래스로 분리하라고 했고, 역할을 나누면 한 파일만 읽어도 이해되며 테스트도 부품별로 할 수 있습니다.

Repository 가 print 를 안 하는 이유는?

로직과 화면을 분리하려고요. 값을 돌려주기만 하면 출력 형식이 바뀌어도 로직을 안 고치고, 테스트도 문자열이 아니라 값으로 검증할 수 있습니다.

잘못된 입력은 어떻게 처리하나요?

Repository 가 MiniGitError("Unknown branch: x") 를 던지고, cli.execute 가 잡아서 메시지를 그대로 출력합니다. 프로그램은 죽지 않습니다. 표준 메시지는 Invalid args, Unknown branch: <name>, Unknown commit: <hash>.

명령 처리를 if/elif 가 아니라 dict 로 한 이유는?

COMMANDS = {"INIT": _cmd_init, ...} 표에서 찾으면 코드가 짧고, 새 명령은 한 줄 추가로 끝납니다. 대소문자 처리도 upper() 한 번으로 통일됩니다.

종료하면 데이터가 사라지는데 괜찮나요?

과제가 "영속성은 구현하지 않아도 된다(메모리 동작으로 충분)"고 했습니다. 확장하려면 커밋들을 JSON 으로 저장·불러오면 됩니다.

추가한 명령(HELP, STATUS, INDEX, USER)은 왜 만들었나요?

HELP·STATUS 는 사용 편의, INDEX 는 역색인 내용을 눈으로 보여주기 위한 시연용입니다. USER 는 INIT 이 저장소를 초기화해서 한 저장소에 여러 작성자 커밋을 만들 수 없는 문제를 풀려고 넣었습니다(--author 검색과 작성자 정렬을 의미 있게 보여 주기 위함). 과제 요구 명령의 동작은 바꾸지 않습니다.

DAG · 그래프

★트리도 아니고 리스트도 아닌 DAG 인 이유?

브랜치가 갈라지면 한 부모에 자식이 여럿(트리 형태)이고, 병합 커밋은 부모가 여럿이라 트리가 아닙니다. 방향이 있고(자식→부모) 순환이 없는 그래프 = DAG.

화살표 방향이 왜 자식→부모인가요?

실제 Git 도 커밋이 부모의 hash 를 저장합니다. 부모는 자식을 모릅니다. 그래서 자식 방향이 필요한 PATH·위상 정렬을 위해 _children 을 따로 기록했습니다.

부모가 없는 커밋도 가능한가요?

네, 첫 커밋(뿌리)입니다. 첫 커밋 전에 만든 브랜치에서 커밋하면 뿌리가 2개가 되기도 합니다 → 그때 PATH 는 No path.

🔥 병합(merge) 커밋은 지원하나요?

데이터 구조와 알고리즘은 이미 지원합니다(parents 가 리스트, 테스트에서 부모 2개짜리로 위상 정렬·조상·경로 검증). 다만 merge 명령은 보너스 과제라 구현하지 않았습니다. 추가하려면 6-4 의 15줄 스케치처럼 부모를 2개로 만들면 됩니다.

커밋 저장소가 "해시맵 기반"이라는 건 어디서 보이나요?

CommitGraph._commits: dict[str, Commit]. 키가 hash 이고 조회가 평균 O(1) 입니다. 파이썬 dict 가 해시맵입니다.

위상 정렬 · LOG

★Kahn 알고리즘을 말로 설명해 보세요.

목표 2 대본 그대로: 대기 부모 수가 0 인 커밋부터 큐에서 꺼내 출력하고, 자식들의 대기 수를 1 줄여 0 이 되면 큐에 넣는다. 큐가 빌 때까지 반복.

시연에서 c005 가 c004 보다 먼저 나온 이유는?

c003 을 처리할 때 자식 c004 가 큐 뒤에 들어가는데, 그 전에 c002 를 처리하면서 c005 가 이미 큐에 있었기 때문입니다. 부모 먼저 규칙(c004 의 부모 c003, c005 의 부모 c002 가 먼저 나옴)은 지켜집니다. 위상 순서는 여러 가지가 가능합니다.

시간복잡도는? 순환은 어떻게 감지하나요?

O(V+E). 순환이 있으면 일부 커밋이 대기 수 0 이 못 돼 큐에 안 들어가므로 출력 개수 < 전체 개수 → cycle detected.

queue 를 pop(0) 으로 안 쓰고 front 번호를 쓴 이유는?

리스트 맨 앞 pop(0) 은 나머지를 전부 당겨서 O(n) 입니다. 위치 번호만 앞으로 밀면 O(1) 이라 전체가 O(V+E) 로 유지됩니다.

PATH · ANCESTORS

★동률일 때 사전순 최소 경로를 어떻게 보장하나요?

목표 3 설명: 도착점 BFS 거리표 → 출발점에서 거리 −1 이웃 중 가장 작은 hash 선택 반복. 최단 경로는 모두 같은 길이라 앞 칸부터 최소를 고르면 전체가 최소. 임의 DAG 로 "전체 경로 나열" 정답과 비교하는 테스트로 검증했습니다.

🔥 hash 길이가 다르면(c9 vs c10) 문자열 사전순과 원소 비교가 달라지지 않나요?

문제는 "h1->h2->… 문자열의 사전순"이고, 구분자 -(아스키 45)가 숫자·영문자보다 작아서 "c1->"가 "c10"보다 앞섭니다. 원소 단위 비교(짧은 쪽이 접두사면 앞)와 결과가 같습니다. 그리고 파이썬 문자열 비교 neighbor < best 는 그대로 사전순입니다.

PATH c001 c001 처럼 같은 커밋이면?

거리 0 이라 Path: c001 한 개만 나옵니다.

ANCESTORS 에 자기 자신이 포함되나요? 순서는?

자기 자신은 제외합니다("조상"이므로). 가까운 조상부터(BFS 순서) 나옵니다. 과제는 순서를 요구하지 않고 "빠짐없이"가 핵심입니다.

No path 는 언제 나오나요?

두 커밋이 서로 다른 뿌리에서 시작해 이어져 있지 않을 때입니다. 만드는 방법은 6-1 의 "No path 시연".

모든 경로를 나열한 뒤 가장 짧은 걸 고르면 안 되나요?

가능은 하지만 커밋과 병합이 늘면 경로 수가 지수적으로 폭발합니다. BFS 는 O(V+E) 로 끝납니다. (테스트에서는 작은 그래프에 한해 정답 확인용으로만 전체 나열을 씁니다.)

정렬

★안정 정렬이 뭐고, 어디서 보장되나요?

키가 같은 항목끼리 원래 순서를 유지하는 정렬. _merge 의 <= 때문에 같을 때 왼쪽(원래 앞쪽)을 먼저 꺼냅니다.

왜 병합 정렬을 골랐나요? 퀵 정렬이 아니라?

퀵 정렬은 최악 O(n²) 이고 불안정합니다. 병합 정렬은 최악도 O(n log n) 이고 안정이라, 동률 처리를 입력 순서(부모 먼저)로 자연스럽게 할 수 있습니다. 대가는 O(n) 추가 메모리.

key 함수는 왜 쓰나요?

정렬 코드 한 벌에 "무엇을 비교할지"만 갈아 끼우려고요. 날짜순은 lambda c: c.timestamp, 작성자순은 lambda c: c.author.lower().

🔥 LOG 의 정렬 옵션 결과는 여전히 "부모 먼저"인가요?

아닙니다. --sort-by 는 지정한 기준만으로 정렬합니다(작성자순은 부모 자식 순서가 깨질 수 있음). 기본 LOG 만 부모 먼저를 보장합니다. 동률만 위상 순서가 유지됩니다.

🔥 같은 초에 만든 커밋들을 날짜순 정렬하면 어떻게 되나요?

timestamp 가 전부 같으니 "동률"입니다. 병합 정렬이 안정 정렬이라 입력 순서(= 위상 순서)가 그대로 유지됩니다. 즉 log 와 같은 순서가 나옵니다. 동률일 때 결과가 흔들리지 않는 것이 안정 정렬을 고른 이유 중 하나입니다.

원본 리스트를 바꾸나요?

아니요, 새 리스트를 돌려줍니다(list(items) 복사, 슬라이싱). 테스트 test_sorted_order_permutation_and_original_untouched 로 확인.

역색인 · 검색

★역색인이 순회 검색보다 빠른 이유?

목표 5. 순회는 O(N) 로 커밋 수에 비례, 역색인은 dict 조회 평균 O(1) + 결과 개수 K. 테스트 test_search_uses_index_not_scan 은 커밋 500개 중 1개를 찾을 때 커밋을 1번만 꺼내는지 확인합니다.

역색인의 단점은?

커밋 때마다 인덱스를 갱신해야 하고(쓰기 비용), 단어×목록만큼 메모리를 더 씁니다. 읽기가 많은 경우에 이득입니다.

저장할 때와 검색할 때 규칙이 왜 같아야 하나요?

저장은 소문자로 하는데 검색을 "Login" 그대로 하면 못 찾습니다. 그래서 lower() 규칙을 양쪽에 똑같이 적용합니다. 작성자도 소문자 키로 저장해 --author=ALICE 로도 찾습니다.

커밋을 수정·삭제하면 인덱스는요?

이 프로그램은 커밋이 불변(만든 뒤 수정·삭제 없음)이라 필요 없습니다. 실제 Git 커밋도 불변입니다.

★hash 가 겹치지 않는다고 어떻게 보장하나요?

HashGenerator 가 카운터를 1씩 올리기만 하므로 같은 번호가 두 번 나올 수 없습니다. 저장소 add 에서도 중복 hash 를 거부합니다. INIT 을 다시 해도 발급기는 유지돼 세션 전체에서 유일합니다. 테스트: INIT 3회 × 400커밋 = 1200개 모두 서로 다름.

진짜 Git 처럼 SHA-1 로 안 한 이유는?

과제가 구현 방식은 자유(카운터 등)라고 했고, 카운터가 유일성을 가장 단순하게 보장하며 직접 입력하기 쉽습니다. 내용 해시로 바꾸는 법은 6-4 에 있습니다 — 겹치면 카운터를 올려 다시 만드는 루프로 유일성을 유지합니다.

BRANCH 는 커밋을 복사하나요? HEAD 는 무엇인가요?

복사하지 않고 같은 커밋을 가리키는 이름표를 하나 더 만듭니다(branches[new] = branches[head]). HEAD 는 현재 올라탄 브랜치 이름이고, COMMIT 하면 그 브랜치 이름표만 새 커밋으로 이동합니다.

INIT 을 두 번 하면?

저장소(커밋·브랜치·인덱스)가 비워지고 새로 시작합니다. 단, hash 번호는 이어집니다.

첫 커밋 전에 BRANCH 를 허용한 이유는?

"현재 HEAD 가 가리키는 커밋"이 없을 때도 이름표를 만들 수 있게 했고(가리키는 곳 None), 덕분에 뿌리 커밋이 2개인 그래프 — 즉 No path 상황 — 을 만들어 볼 수 있습니다.

따옴표 인자는 어떻게 처리하나요?

shlex.split 이 따옴표 안을 한 덩어리로 자릅니다. 닫히지 않은 따옴표는 ValueError → Invalid args. 인자 개수는 _expect 로 검사.

import hashlib                      # models.py 맨 위

class HashGenerator:
    def __init__(self) -> None:
        self._counter = 0
        self._issued: set[str] = set()

    def next_hash(self, seed: str = "") -> str:
        while True:
            self._counter += 1
            candidate = hashlib.sha1(f"{self._counter}:{seed}".encode()).hexdigest()[:7]
            if candidate not in self._issued:
                self._issued.add(candidate)
                return candidate

# repository.py
def merge(self, other: str) -> Commit:
    self.require_init()
    if other not in self.branches:
        raise MiniGitError(f"Unknown branch: {other}")
    mine, theirs = self.branches[self.head], self.branches[other]
    if mine is None or theirs is None or mine == theirs:
        raise MiniGitError("Invalid args")
    commit = Commit(hash=self._hashes.next_hash(), message=f"Merge {other} into {self.head}",
                    author=self.author, timestamp=self._clock(), parents=[mine, theirs])
    self.graph.add(commit)
    self.branches[self.head] = commit.hash
    self.index.add(commit)
    return commit

# cli.py
def _cmd_merge(repo, args):
    _expect(args, 1)
    commit = repo.merge(args[0])
    return [f"[{repo.head} {commit.hash}] {commit.message}"]

8. 용어집

노드(node) / 간선(edge)
그래프의 점 / 선. 여기서 노드 = 커밋, 간선 = 커밋→부모 연결.
DAG
Directed Acyclic Graph. 방향이 있고 순환이 없는 그래프. 커밋 구조가 이것.
뿌리 커밋(root)
부모가 없는 커밋. 보통 첫 커밋.
부모 / 자식 / 조상
부모 = parents 에 적힌 커밋. 자식 = 나를 부모로 가진 커밋. 조상 = 부모, 부모의 부모, … 전부.
브랜치(branch)
커밋 하나를 가리키는 이름표.
HEAD
현재 올라탄 브랜치(커밋이 생기면 따라 움직이는 이름표).
hash
커밋의 고유 이름표 문자열(우리는 c001).
해시맵 / 딕셔너리
키로 값을 평균 O(1) 에 찾는 자료구조. 파이썬 dict.
큐(queue)
먼저 들어온 것을 먼저 꺼내는 줄(FIFO).
스택(stack)
나중에 들어온 것을 먼저 꺼내는 더미(LIFO). DFS 에 쓰임.
BFS / DFS
너비 우선(가까운 곳부터) / 깊이 우선(한 길로 끝까지) 탐색.
위상 정렬(topological sort)
DAG 의 모든 노드를 "화살표 시작점이 항상 앞"이 되도록 한 줄로 세우는 것. 여기서는 부모가 앞.
Kahn 알고리즘
대기 부모 수(진입 차수)가 0 인 것부터 꺼내는 위상 정렬 방법.
진입 차수(in-degree)
한 노드로 들어오는 화살표 수. 여기서는 "아직 출력 안 된 부모 수"로 사용.
역색인(inverted index)
단어 → 그 단어가 있는 문서(커밋) 목록. 책의 찾아보기.
정규화(normalize)
비교하기 쉽게 모양을 통일하는 것. 여기서는 소문자 변환.
병합 정렬(merge sort)
반으로 쪼개 정렬하고 합치는 분할 정복 정렬. O(n log n), 안정.
안정 정렬(stable)
같은 키끼리 원래 순서를 유지하는 정렬.
시간복잡도 / 공간복잡도
입력이 커질 때 일(시간)·메모리(공간)가 늘어나는 정도. 보통 Big-O 로 표기.
V, E, n
V = 노드(커밋) 수, E = 간선(부모 연결) 수, n = 일반적인 입력 크기.
사전순(lexicographic)
사전에 실리는 순서. "c1" < "c10" < "c2" 처럼 글자 하나씩 앞에서부터 비교.
REPL
Read-Eval-Print Loop. 입력→실행→출력을 반복하는 프롬프트.
파싱(parsing)
입력 문자열을 의미 있는 조각(명령, 인자)으로 해석하는 것.
예외(exception)
오류 상황을 알리는 신호. raise 로 던지고 except 로 받는다.
dataclass
데이터 담는 클래스를 짧게 쓰게 해 주는 파이썬 기능.
docstring
함수·클래스 바로 아래에 쓰는 설명 문자열("""...""").
변이 테스트(mutation test)
코드를 일부러 망가뜨려 테스트가 실패하는지 확인해, 테스트의 신뢰도를 점검하는 방법.
