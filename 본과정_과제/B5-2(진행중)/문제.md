# Task5. Mini Git 구현 과제

## 1. 미션 소개

Git의 커밋 하나에는 그래프 자료구조와 해시가 담겨 있습니다. 이 구조를 알고 사용하면 `rebase`, `merge`, `cherry-pick` 같은 명령도 다르게 보이고, 알고리즘 학습과도 자연스럽게 연결됩니다.

Git은 전 세계 개발자들이 사용하는 분산 버전 관리 시스템입니다. 브랜치로 병렬 작업을 지원하고, 변경 이력을 추적하며, 그 핵심에는 그래프 자료구조와 탐색 알고리즘이 있습니다.

이번 미션에서는 Git의 핵심 구조를 직접 구현하며 CLI 기반 Mini Git을 완성합니다. 커밋 구조를 구축하고, 브랜치를 관리하고, 커밋을 검색하고 정렬하는 시스템을 만들면서 실제 Git의 동작 원리를 체득합니다.

이 경험은 다양한 알고리즘 학습의 토대가 되며, 코딩 테스트를 준비하는 데에도 도움이 됩니다.

## 2. 최종 결과물

다음 기능이 정상 동작하는 CLI 기반 Mini Git 프로그램 1개를 완성합니다.

### 저장소 및 브랜치 관리

입력/요청:

```text
INIT <user_name>
BRANCH <branch_name>
SWITCH <branch_name>
COMMIT <message>
```

출력/화면:

- 저장소 초기화 결과
- 브랜치 생성 결과
- 브랜치 전환 결과
- 커밋 생성 결과
- 커밋 생성 시 커밋 hash 포함

### 커밋 로그 및 탐색

입력/요청:

```text
LOG
PATH <commit1> <commit2>
ANCESTORS <commit_hash>
```

출력/화면:

- 커밋 목록 출력
- 두 커밋 사이의 최단 경로 출력
- 경로가 없으면 `No path` 출력
- 특정 커밋의 조상 목록 출력

### 검색 및 정렬

입력/요청:

```text
SEARCH <keyword>
SEARCH --author=<name>
LOG --sort-by=date
LOG --sort-by=author
```

출력/화면:

- 검색 결과 커밋 목록
- 정렬 기준에 따른 로그 출력

### CLI 인터페이스

REPL 방식으로 동작합니다.

```text
mini-git>
```

요구사항:

- `mini-git>` 프롬프트에서 명령을 반복 입력합니다.
- 명령 파싱, 실행, 결과 출력이 반복됩니다.
- `exit` 또는 `quit`로 종료할 수 있습니다.

### 필수 제출물 및 실행

필수 제출물:

- 엔트리 포인트 1개
- 예: `main.py`
- `README.md` 1개

실행 예:

```bash
python main.py
```

## 3. 과제 목표

이 과제를 마친 후, 학습자는 아래 내용을 스스로 설명할 수 있어야 합니다.

- 커밋 그래프를 구현하고, Git의 커밋 구조가 왜 DAG인지 설명할 수 있다.
- 부모가 먼저 출력되는 로그를 만들기 위해 어떤 접근이 필요한지 설명할 수 있다.
- 예: 위상 정렬 성격의 출력
- 두 커밋 사이의 최단 경로를 찾는 방법을 설명할 수 있다.
- 특정 커밋의 모든 조상을 탐색하는 방법을 설명할 수 있다.
- 정렬 알고리즘을 직접 구현하고 평균/최악 시간복잡도를 설명할 수 있다.
- 직접 구현한 정렬이 안정 정렬인지 여부를 설명할 수 있다.
- 역색인의 동작 원리를 설명할 수 있다.
- 역색인이 전체 순회 검색보다 빠른 이유를 시간복잡도 관점에서 설명할 수 있다.

## 4. 기능 요구 사항

다음 요구사항을 모두 만족해야 합니다.

### CLI 공통 규칙

명령어는 대소문자를 구분하지 않습니다.

```text
INIT
init
```

위 두 명령은 모두 허용합니다.

문자열 인자, 예를 들어 사용자명, 커밋 메시지, 검색 키워드는 공백을 포함할 수 있습니다. 공백이 포함될 경우 따옴표로 감쌉니다.

```text
COMMIT "Add login feature"
```

옵션 표기는 아래 형식으로 통일합니다.

```text
SEARCH --author=<name>
LOG --sort-by=date
LOG --sort-by=author
```

잘못된 입력에 대한 최소 에러 메시지를 표준화합니다.

예:

```text
Invalid args
Unknown branch: <name>
Unknown commit: <hash>
```

### 커밋 그래프

커밋 노드는 최소한 아래 필드를 가져야 합니다.

- `hash`
- `message`
- `author`
- `timestamp`
- `parents`

요구사항:

- 각 커밋은 0개 이상의 부모 커밋을 가질 수 있습니다.
- 커밋 그래프는 DAG 구조여야 합니다.
- DAG는 방향성 비순환 그래프입니다.
- 커밋 저장소는 커밋 hash로 빠르게 찾을 수 있어야 합니다.
- 예: 해시맵 기반
- 커밋 hash는 세션 내에서 유일해야 합니다.
- 중복 hash가 발생하면 안 됩니다.
- 구현 방식은 자유입니다.
- 예: 증가 카운터 기반, 난수 기반 등
- 단, 중복이 발생하지 않도록 보장해야 합니다.

### 역색인

검색 시 모든 커밋을 순회하지 않고 후보 커밋을 빠르게 가져올 수 있어야 합니다.

키워드 추출 최소 기준:

- 커밋 메시지를 공백 기준으로 분리합니다.
- 분리한 토큰을 소문자로 정규화합니다.
- 정규화한 토큰을 키워드로 저장합니다.

최소 2종 인덱스를 지원해야 합니다.

```text
keyword -> commit_hash 목록
author  -> commit_hash 목록
```

### 정렬 알고리즘 직접 구현

Python 표준 정렬 API 사용은 금지합니다.

금지:

```python
sorted()
list.sort()
```

요구사항:

- 정렬 알고리즘을 직접 구현해야 합니다.
- 비교 기준을 바꿔 정렬할 수 있어야 합니다.
- 예: 날짜 기준 정렬
- 예: 작성자 기준 정렬

## 5. 명령어 기능 요구

### INIT

형식:

```text
INIT <user_name>
```

기능:

- 저장소를 초기화합니다.
- `main` 브랜치를 생성합니다.
- `HEAD`를 `main` 브랜치로 설정합니다.
- 현재 사용자 `author`를 설정합니다.

### BRANCH

형식:

```text
BRANCH <branch_name>
```

기능:

- 현재 커밋, 즉 `HEAD`를 가리키는 새 브랜치를 생성합니다.

### SWITCH

형식:

```text
SWITCH <branch_name>
```

기능:

- `HEAD`를 지정한 브랜치로 이동합니다.

### COMMIT

형식:

```text
COMMIT <message>
```

기능:

- 현재 `HEAD`를 부모로 하는 새 커밋을 생성합니다.
- 커밋 생성 시 역색인을 갱신합니다.
- 갱신 대상은 author 인덱스와 keyword 인덱스입니다.

### LOG

형식:

```text
LOG
```

기능:

- 커밋 목록을 출력합니다.
- 학습 목적상 단순 최신순 나열이 아닙니다.
- 부모 커밋이 항상 자식 커밋보다 먼저 출력되도록 출력합니다.
- 위상 정렬 성격의 출력입니다.

출력 포맷:

- 자유롭게 정할 수 있습니다.
- 단, 아래 정보는 식별 가능해야 합니다.
- 커밋 hash
- author
- timestamp
- message

### LOG 정렬 옵션

형식:

```text
LOG --sort-by=date
LOG --sort-by=author
```

기능:

- `date`: timestamp 기준으로 정렬합니다.
- `author`: 작성자 이름 기준으로 정렬합니다.
- 동률 처리 규칙은 자유입니다.

### PATH

형식:

```text
PATH <commit1> <commit2>
```

기능:

- 두 커밋 사이의 최단 경로를 출력합니다.
- 최단 경로는 커밋-부모 연결을 무방향 간선으로 간주했을 때의 최단 경로입니다.
- 간선 수가 가장 적은 경로를 선택합니다.
- 경로가 없으면 `No path`를 출력합니다.

최단 경로가 여러 개일 경우:

- 경로를 `hash1->hash2->...` 문자열로 만들었을 때 사전순이 가장 작은 경로를 선택합니다.

### ANCESTORS

형식:

```text
ANCESTORS <commit_hash>
```

기능:

- 해당 커밋에서 도달 가능한 모든 조상 커밋을 빠짐없이 출력합니다.

### SEARCH

형식:

```text
SEARCH <keyword>
```

기능:

- 키워드가 포함된 커밋 메시지의 커밋들을 출력합니다.
- 검색은 역색인 기반으로 동작해야 합니다.

### SEARCH author 옵션

형식:

```text
SEARCH --author=<name>
```

기능:

- 특정 작성자의 커밋들을 출력합니다.
- 검색은 역색인 기반으로 동작해야 합니다.
