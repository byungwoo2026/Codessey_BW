## 이슈 #1 — AWS 계정 신규 가입 중 계정 정지

| 항목 | 내용 |
|---|---|
| 증상(문제 상황) | AWS 신규 계정 가입 중, 플랜 선택(Free/Paid) 화면에서 브라우저 뒤로 가기로 이전 화면을 다시 열었다가 가입 흐름이 끊김. 이후 같은 이메일로 로그인 시 "계정이 정지되어 인증에 실패했습니다" 화면이 표시됨 |
| 원인 가설 | 가입 절차(이메일 인증 → 비밀번호 → 결제 정보 → 휴대폰 인증 → 플랜 선택)가 완료되기 전에 브라우저 탐색(뒤로 가기)으로 흐름이 중단되어, AWS 측에서 미완료 계정을 정지 상태로 처리한 것으로 추정 |
| 검증 방법 | 가입 시 사용한 이메일로 "AWS 계정이 이미 존재합니다" 안내 메일을 수신하여, 동일 이메일로는 재가입이 불가능함을 확인 |
| 조치 내용 | 다른 이메일 주소로 신규 가입을 처음부터 다시 진행. 가입 완료 전까지 뒤로 가기/새로고침/탭 닫기를 하지 않음 |
| 결과 | 신규 가입 정상 완료, 활성화 메일 수신하여 Free 플랜(6개월, $100~$200 크레딧) 확인 |
| 재발 방지 | AWS 계정 가입은 반드시 한 번에 끝까지 진행하고, 진행 중간에 이전 화면 확인이 필요하면 가입 완료 후 콘솔에서 확인한다 |

## 이슈 #2 — VPC 서브넷 생성 시 IPv4 CIDR 입력 칸에 값이 입력되지 않음

| 항목 | 내용 |
|---|---|
| 증상(문제 상황) | "서브넷 생성" 화면의 IPv4 서브넷 CIDR 블록 입력 칸에 `10.0.1.0/24`를 타이핑해도 기존 예시값(`10.0.0.0/20`)이 지워지지 않고 반영되지 않음 |
| 원인 가설 | AWS 콘솔이 최근 개편되며 CIDR 입력 칸이 일반 텍스트 필드가 아닌 세그먼트(옥텟) 단위 편집 위젯으로 바뀌었고, 클릭 위치에 따라 커서가 올바른 세그먼트에 위치하지 않아 입력이 무시된 것으로 추정 |
| 검증 방법 | 입력 칸을 더블클릭하여 특정 세그먼트만 선택되는지 확인, 이후 커서를 칸 안에 둔 채 값이 반영되는지 재시도 |
| 조치 내용 | 입력 칸을 한 번 클릭해 포커스를 준 뒤 값을 입력하자 정상적으로 `10.0.1.0/24 (256 IPs)`로 반영됨 |
| 결과 | 서브넷이 의도한 CIDR(`10.0.1.0/24`)로 정상 생성됨 |
| 재발 방지 | AWS 콘솔의 CIDR/IP 입력 칸은 입력 전 반드시 칸 안을 클릭해 포커스를 확인하고, 입력 후에는 화면에 표시된 값을 다시 읽어 의도한 값과 일치하는지 확인한다 |

## 이슈 #3 — EC2 인스턴스 시작 시 보안 그룹 검증 권한 경고

| 항목 | 내용 |
|---|---|
| 증상(문제 상황) | "인스턴스 시작" 화면에서 기존 보안 그룹(`mission-b61-public-sg`)을 선택하자 "ec2:GetSecurityGroupsForVpc 작업을 수행할 권한이 없습니다"라는 노란색 경고가 표시됨 |
| 원인 가설 | 최소 권한으로 직접 작성한 IAM 정책(`MissionB61-EC2VPC-LeastPrivilege`)에 콘솔이 보안 그룹 유효성을 사전 점검할 때 쓰는 `ec2:GetSecurityGroupsForVpc` 조회 액션이 포함되지 않아 발생한 경고 |
| 검증 방법 | 경고를 무시하고 "인스턴스 시작" 버튼을 눌러 실제로 인스턴스 생성이 차단되는지 확인 |
| 조치 내용 | 별도 조치 없이 그대로 진행 — 이 경고는 콘솔의 사전 점검(조회)용 권한이 없다는 안내일 뿐, 정책에 이미 포함된 `ec2:RunInstances` 등 실제 생성 권한에는 영향이 없었음 |
| 결과 | 인스턴스가 정상적으로 시작됨 (`i-03d20dd8d7eb3263a`, 실행 중) |
| 재발 방지 | 최소 권한 정책 작성 시 실제 리소스 생성/삭제 액션뿐 아니라 콘솔이 화면 표시를 위해 부가적으로 호출하는 조회(Describe/Get) 액션까지 고려하되, 경고가 뜨더라도 곧바로 정책을 수정하기보다 먼저 실제 동작이 차단되는지 확인한다 |
| 참고 (같은 계열) | 정리 단계(2026-10-05)에 증빙 캡처와 삭제를 진행하면서 같은 종류의 권한 부족 안내가 세 번 더 확인됨. ① VPC 상세 "세부 정보"의 "Route 53 Resolver DNS 방화벽 규칙 그룹 — 규칙 그룹 로드 실패", ② EC2 인스턴스 상세의 "AWS Compute Optimizer 찾기 — compute-optimizer:GetEnrollmentStatus 권한 없음", ③ 서브넷 삭제 확인 창의 "리소스 공유를 로드하지 못했습니다 — ram:GetResourceShareAssociations 권한 없음" 메시지. 모두 이번 과제 범위(VPC/EC2) 밖 서비스의 조회 권한이 정책에 없어서 나타난 것으로, 최소 권한 원칙에 따라 의도적으로 포함하지 않았고 VPC·EC2 구성과 삭제 동작에는 영향이 없었음 |

### 자주 발생하는 후보 원인 (참고용 — 실제 겪은 문제만 위 표에 기록)

- 외부 접속 실패(80): Security Group에 80 포트 인바운드 규칙 누락, 또는 Nginx 미실행
- 외부 접속 실패(전체): Route Table에 `0.0.0.0/0 → IGW` 경로 누락, 또는 Subnet이 Private으로 잘못 연결됨
- SSH 접속 실패: 22 포트 소스 IP 불일치, 키페어 권한 오류(`chmod 400 key.pem` 필요)
- 아웃바운드 실패(`curl example.com` 실패): Route Table 경로 누락, 또는 Security Group 아웃바운드 규칙이 과도하게 제한됨
