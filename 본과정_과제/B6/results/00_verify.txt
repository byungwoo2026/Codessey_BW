[제약조건이 실제로 동작하는지 확인]  잘못된 입력을 일부러 시도 → 모두 거부되어야 한다 (시도 후 자동 롤백)

(1) FK : 존재하지 않는 회원(999번)으로 대여 기록 입력
    SQL   : INSERT INTO rental (member_id, book_id, rented_at, due_date) VALUES (999, 1, '2026-10-08', '2026-10-22')
    결과  : 거부됨 → IntegrityError: FOREIGN KEY constraint failed

(2) FK : 존재하지 않는 도서(999번)로 대여 기록 입력
    SQL   : INSERT INTO rental (member_id, book_id, rented_at, due_date) VALUES (1, 999, '2026-10-08', '2026-10-22')
    결과  : 거부됨 → IntegrityError: FOREIGN KEY constraint failed

(3) FK : 존재하지 않는 분류(99번)로 도서 입력
    SQL   : INSERT INTO book (category_id, title, author, price) VALUES (99, '유령 책', '아무개', 10000)
    결과  : 거부됨 → IntegrityError: FOREIGN KEY constraint failed

(4) FK(RESTRICT) : 대여 기록이 남아 있는 도서(1번) 삭제
    SQL   : DELETE FROM book WHERE book_id = 1
    결과  : 거부됨 → IntegrityError: FOREIGN KEY constraint failed

(5) FK(RESTRICT) : 대여 기록이 남아 있는 회원(1번) 삭제
    SQL   : DELETE FROM member WHERE member_id = 1
    결과  : 거부됨 → IntegrityError: FOREIGN KEY constraint failed

(6) NOT NULL : 이름 없이 회원 입력
    SQL   : INSERT INTO member (name, email, joined_at) VALUES (NULL, 'null.name@example.com', '2026-10-08')
    결과  : 거부됨 → IntegrityError: NOT NULL constraint failed: member.name

(7) UNIQUE : 이미 있는 이메일로 회원 입력
    SQL   : INSERT INTO member (name, email, joined_at) VALUES ('중복', 'minjun.kim@example.com', '2026-10-08')
    결과  : 거부됨 → IntegrityError: UNIQUE constraint failed: member.email

(8) UNIQUE : 이미 있는 분류 이름 입력
    SQL   : INSERT INTO category (name) VALUES ('소설')
    결과  : 거부됨 → IntegrityError: UNIQUE constraint failed: category.name

(9) CHECK : 음수 가격으로 도서 입력
    SQL   : INSERT INTO book (category_id, title, author, price) VALUES (1, '음수 책', '아무개', -1)
    결과  : 거부됨 → IntegrityError: CHECK constraint failed: ck_book_price

(10) CHECK : 허용되지 않은 상태값('LOST')으로 대여 기록 입력
    SQL   : INSERT INTO rental (member_id, book_id, rented_at, due_date, status) VALUES (1, 1, '2026-10-08', '2026-10-22', 'LOST')
    결과  : 거부됨 → IntegrityError: CHECK constraint failed: ck_rental_status
